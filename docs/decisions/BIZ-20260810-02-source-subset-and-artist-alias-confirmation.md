## 决策问题

固定抓取四个平台、固定生成四个歌单会让用户无法跳过不需要或暂不可用的平台。现有歌手解析又只保留规范化后完全同名的首项；输入“刘雨昕”时，网易正确艺人的展示名“刘雨昕XIN LIU”被排除，另一个完全同名候选可能被直接选中。需要在不引入任意模糊匹配的前提下，让用户核对正确身份，并分别控制本次请求哪些 Provider、从已抓取结果生成哪些歌单。

## 决策

### 1. 歌手解析使用精确全名或精确别名段候选

每个已选抓取来源继续只接受规范化完整展示名；网易为组合展示名增加第二种严格匹配：

1. `exact`：去除首尾空白、统一 Unicode 兼容字符、折叠分隔空白并对拉丁字母忽略大小写后，输入名称与 Provider 完整展示名相等。
2. `alias_exact`：输入和 Provider 展示名中恰有一方是“完整连续汉字段 + 完整拉丁字母段”或相反顺序的双脚本组合名，另一方必须与其中一个完整脚本段相等；拉丁段至少包含两个字母，可包含单词间空白。

例如“刘雨昕XIN LIU”可以在汉字到拉丁字母的脚本边界拆为“刘雨昕”和“XIN LIU”，因此输入“刘雨昕”可形成 `alias_exact` 候选。输入“刘雨”不是任何完整名称段，不得匹配该艺人。

禁止使用任意 `contains`、未闭合前缀或后缀、编辑距离、拼音推断、专辑数量或头像相似度决定身份。各 adapter 按 Provider 原始稳定顺序扫描搜索结果并选择首个合法结果；网易的 `exact` 与 `alias_exact` 资格相同，不得先在全部结果中全局查找 `exact`、再回退 `alias_exact`，否则后置完全同名项会遮蔽 Provider 排在前面的正确别名展示项。

系统等待全部已选抓取来源的身份解析抵达，再处理统一确认。解析成功的来源形成成功身份子集；失败、无匹配或身份非法的来源直接保留为可定位的 `failed`，不参与确认，也不阻断成功身份子集继续。

成功身份子集非空时只弹出一次统一确认：界面展示来源、Provider 完整展示名、头像、来源内 ID 和可用的声明专辑数；用户确认后只为该成功身份子集开始专辑请求，取消或关闭则不开始任何专辑请求。成功身份子集为空时不弹确认，批次直接 `blocked`。不得跨来源复用身份。

### 2. 抓取前选择来源，默认全选

页面在“获取并预览”前提供酷狗、QQ、网易和酷我四个抓取来源复选项，初始默认全部选中。

- 用户可选择任意一至四个平台；零个来源时禁用获取并预览，不发起 Provider 请求。
- 只有本次选择的来源参与身份解析、进度、取消和重试；确认和目录请求只覆盖身份解析成功的非空子集。已选但解析失败的来源保留 `failed` 摘要，未选来源不请求、不生成空快照，也不记为失败。
- 点击获取后将有序 `requestedSources` 固化到新 `batchId`。改变抓取来源不会就地拼接当前快照，必须由用户再次点击获取并预览，以新批次替换旧结果。
- 所选来源按全局稳定顺序 `kg -> tx -> wy -> kw` 展示和协调，来源子集不改变每个 adapter 的分页、并发、重试、取消或完整性规则。

### 3. 抓取后选择生成歌单的来源，默认全选可用项

目录抓取结束后，页面只为本批次已抓取且满足写入条件的来源提供“生成歌单”复选项。初始默认选中全部可用项。

- `complete` 或非空 `partial` 且最终去重后至少一首合法歌曲的来源可选。
- `failed`、`cancelled` 或最终为零首的来源不可选，并在对应来源摘要中说明原因；它们不再阻断用户从其他合格快照选择生成子集。
- 用户可以在可用项中选择任意非空子集；零个生成来源时禁用创建，不进行同名检查或写入。
- 切换生成来源只改变当前快照的写入子集，不请求 Provider、不修改快照，也不改变其完整性状态和去重核查。

### 4. 生成子集保持全有或全无

批量创建只校验并处理用户最终选中的 `playlistSources`：

1. 每项必须属于当前 `batchId` 的 `requestedSources`，拥有 `complete/partial` 非空快照，并且不得重复。
2. 目标名称、曲数预览和同名检查只列出选中项；名称继续使用“`<输入歌手名>-<酷狗|qq|网易|酷我>-<N>首`”，`N` 仍为该来源最终实际提交歌曲数。
3. 核心按稳定来源顺序过滤后创建选中歌单。任一创建或加歌失败时，尽力回滚本次已创建的全部选中项；未选来源和批次前既有歌单不得删除或修改。
4. 只有选中子集全部成功才返回成功。补偿失败继续报告选中子集中的全部残留名称和 ID。

“全有或全无”从固定四歌单收敛为本次选中生成子集的全有或全无；未选来源不属于本次创建目标，也不构成部分成功。

### 5. 两组选择随当前会话状态保留

页面级会话状态在既有 `KeepAlive` 边界内增加：

- 抓取前的 `requestedSources`。
- 抓取后的 `playlistSources`。

普通路由切换后返回时，继续展示同一输入、`batchId`、已抓取来源快照、两组选择、来源摘要、去重核查和 apply 结果，不自动请求 Provider。显式重新获取会创建新 `batchId`、按当时的 `requestedSources` 重建快照、清空旧 apply 结果，并把 `playlistSources` 初始化为新批次全部可用来源。刷新或重启仍从空快照和四个抓取来源默认全选开始。

### 6. 其他目录和歌单规则不变

每个被抓取来源继续自动使用该来源全部合法专辑，不恢复逐专辑明细或专辑选择；来源内去重核查、非空 `partial`、普通本地歌单、数量命名、同名提示后新建、不自动下载和跨来源不合并规则保持不变。

## 被比较的替代方案

### 方案 A：全局优先选择完全同名项

不采用。完全同名也可能是另一个主体，并会遮蔽 Provider 稳定顺序中更靠前的“刘雨昕XIN LIU”这类合法别名展示项；正确做法是在原始顺序中选择首个严格合法匹配，再通过统一确认展示 Provider 原名和 ID。

### 方案 B：对 Provider 名称使用任意包含匹配

不采用。短输入可能命中不相关长名称，无法形成可解释、可测试的身份边界。

### 方案 C：抓取来源和生成来源共用一组不可变选择

不采用。用户可能需要先查看某来源完整性，再决定是否为该来源创建歌单；两阶段选择必须分离。

### 方案 D：生成子集逐项成功、失败项保留

不采用。同一次创建会留下难以判断的部分结果；选中子集继续采用尽力补偿的全有或全无目标。

## 决策问题

歌手表格已经持续展示歌曲数和目标名称，“查看详情”再次列出歌手汇总、歌手目标名称及每张专辑的正常目标信息，会让真正需要人工核查的异常和阻塞原因被长列表淹没。详情应成为异常核查入口，而不是重复一份正常整理计划。

## 决策

1. 歌手行继续展示歌曲数、目标名称、状态和操作，不改变重命名计划及执行范围。
2. 点击“查看详情”后只展示该歌手当前的阻塞原因和异常记录，不再重复歌手汇总、歌手目标名称或逐专辑正常信息。
3. 异常记录必须保留人工定位所需的相对路径、类型、状态、大小和具体原因；重复硬链接还必须能定位保留路径与待清理路径。
4. 同一歌手既有阻塞又有异常时，两类信息都展示；没有任何阻塞或异常时，只显示一句简洁的“未发现异常或操作阻塞。”，不得回退为专辑列表。
5. 清理预览、清理确认、重命名结果和恢复结果继续使用同一详情弹窗，并保留其逐项目标和结果信息；本决策只收敛用户主动点击“查看详情”时的普通扫描详情。

## 对既有决策的修订

- 修订 `BIZ-20260806-03` 第 6、8 节：详情只承担异常与阻塞核查，不再展示完整专辑预览；唯一物理文件计数和重命名目标规则不变。
- 修订 `BIZ-20260807-03` 第 7 节：移除歌手专辑数量及专辑目标名称进入详情的要求；清理预览和操作结果仍保留完整目标信息。
- 修订 `BIZ-20260808-02` 第 2 节：普通“查看详情”弹窗只展示异常、状态和阻塞原因；长内容滚动、路径复制、单弹窗时序和操作结果反馈规则不变。

上述旧决策未被修订的扫描、清理、重命名、路由保活和数据安全条款继续有效，状态保持 `accepted`。

## 被比较的替代方案

### 方案 A：继续展示全部专辑，但默认折叠

不采用。正常信息仍会增加核查层级，并与表格中的歌曲数和目标名称重复；详情的首要任务是定位异常。

### 方案 B：无异常时不打开弹窗

不采用。按钮点击后没有反馈会被误解为失效；一句简洁提示可以确认扫描确实未发现异常或阻塞。

## 确认项

- [x] 普通“查看详情”不展示歌手汇总、歌手目标名称或逐专辑正常信息。
- [x] 有异常或阻塞时只展示对应核查信息，并保留可人工定位的路径和原因。
- [x] 无异常或阻塞时只显示一句简洁提示。
- [x] 清理确认和操作结果弹窗不因本次收敛而丢失目标或执行结果。

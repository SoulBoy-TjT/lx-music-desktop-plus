# 歌曲整理操作进度与失败核查留存

## 决策问题

当前页面移除了固定扫描状态，但也没有为用户主动触发的重命名提供任何可见进度。清理或重命名失败只在瞬时结果弹窗中出现，自动重扫后再次点击“查看详情”会只读取新快照，导致刚发生的失败无法定位核查。

## 决策

1. “不固定展示扫描状态”的既有决定继续有效；用户主动触发的重命名属于磁盘操作，必须从发起到终态持续展示独立操作进度，不得借扫描状态替代。清理继续使用预览、终态结果和失败核查反馈，不要求伪造逐项数值进度。
2. 重命名进度至少展示操作阶段、已完成步骤数、总步骤数和当前相对目标；进入回滚时明确切换为回滚阶段。无法可靠计算百分比时只展示真实计数，不伪造进度。
3. 清理、重命名及操作日志失败中的 `failed`、`rollbackFailed` 和具有异常原因的 `skipped` 记录，按歌手保留在当前 Renderer 会话中。自动重扫不得清除这些记录。
4. 普通“查看详情”继续不展示成功步骤、歌手汇总、目标名称或逐专辑正常信息；它在当前扫描阻塞与异常之后追加该歌手最近一次操作异常。三类信息均为空时才显示“未发现异常或操作阻塞。”。
5. 同一歌手发起下一次清理或重命名时替换其旧操作异常；切换歌曲整理根目录或应用重启时清空会话记录，不跨根目录、跨重启持久化。
6. 初始操作日志无法可靠落盘时必须在任何磁盘修改前失败，并把日志错误作为该歌手可核查的操作异常；不得继续执行或报告部分成功。
7. 音频扫描提速不得跳过完整解码、复用跨扫描结果或减少唯一物理音频的校验次数；只允许使用有上限的并发和不改变结果顺序的调度优化。

## 对既有决策的修订

- 修订 `BIZ-20260808-02`：移除的是固定扫描状态，不是用户主动磁盘操作的进度反馈。
- 修订 `BIZ-20260810-03`：普通详情仍以异常与阻塞为唯一内容，但“异常”同时包含当前会话内该歌手最近一次操作异常；成功明细仍不进入普通详情。

## 确认项

- [x] 重命名必须显示真实步骤进度，回滚阶段单独标识。
- [x] 自动重扫后仍能从同一歌手“查看详情”核查最近一次操作失败。
- [x] 成功步骤不进入普通详情；新操作、根目录变化和应用重启按规则清理旧失败。
- [x] 扫描优化继续完整解码全部唯一音频，不引入跨扫描缓存。

# 歌手专辑目录口径与来源策略

## 决策问题

“获取一个歌手的全专辑”存在多种含义：只要正式录音室专辑，还是包含 EP、单曲、现场、精选、豪华版、重制版和合作作品；是一个平台的目录，还是跨平台合并后的推断全集。平台返回字段不足以稳定支持所有分类，如果不先固定口径，完成状态、去重规则和验收数量都无法确定。

## 推荐决策

### 1. 输入使用精确歌手引用

第一阶段要求用户选择来源并输入该来源的歌手 ID 或歌手页面链接。系统验证后显示歌手名称供确认。

- 不以歌手名称直接自动选择结果。
- 同名歌手消歧和歌手名称搜索留到后续需求。

> 2026-08-09 起，本节输入方式由 [BIZ-20260809-02](BIZ-20260809-02-tool-input-directory-and-icons.md) 局部修订为“歌手名称完全匹配搜索 + 歌手确认”；数字 ID 和官方链接仅作为兼容输入。其余来源与身份确认规则保持有效。

### 2. 一次生成只使用一个来源

一次目录生成只对应一个来源和一个歌手引用。第一阶段仅支持 `kg`：现有代码中只有酷狗同时具备歌手专辑列表和逐专辑详情实现，能够验证完整专辑曲目。

- 不在第一阶段跨平台合并专辑。
- `wy`、`tx` 只有在补齐可靠的专辑详情 adapter 并单独验收后才能加入支持来源。

> 2026-08-09 起，本节由 [BIZ-20260809-03](BIZ-20260809-03-four-source-discography-playlist-strategy.md) 对新的四平台批次入口作局部修订：一次共同输入会生成 `kg/tx/wy/kw` 四份独立来源快照，但仍不做跨来源合并。本节继续记录酷狗第一阶段和单份目录快照的历史边界。

### 3. “全专辑”采用来源目录原样口径

歌手专辑目录包含选定来源在获取时刻返回的全部专辑条目，以及每张专辑详情返回的完整曲目。只要 Provider 把发行物列在该歌手专辑列表中，就保留该条目，包括可能存在的正式专辑、EP、单曲、现场、精选、豪华版和重制版。

理由：

- 当前来源返回的发行类型字段不统一，强行按名称或类型过滤会漏歌。
- 用户目标是取得完整专辑，不能只保留把目标歌手列为曲目艺人的歌曲；合作、伴奏、序曲等专辑曲目也必须保留。
- 界面按专辑分组展示，用户可以在创建歌单前取消选择不需要的发行物。

### 4. 使用专辑 ID 判断成员关系

- 专辑及曲目归属以来源内专辑 ID 为准，完整曲目以专辑详情结果为准。
- 每张专辑都必须调用专辑详情并以其结果成稿；歌手歌曲列表只可用于提前分组、异常提示或请求调度，不得用于跳过专辑详情或证明专辑完整。
- 目标歌手专辑中的合作、伴奏、序曲及其他完整曲目保留，不再按目标歌手名称过滤。
- 目标歌手参与、但专辑不在其歌手专辑列表中的其他歌手作品不纳入。
- 不同专辑 ID 即使同名也作为不同发行版本保留。
- 同一来源内相同歌曲 ID 去重，不进行按歌名去重。

### 5. 部分结果不能伪装成全量

分页失败、数量不一致或 Provider 返回异常时，目录快照标记为 `partial` 或 `failed`。

- 默认不允许直接创建歌单。
- 用户查看完整性报告并明确接受后，可以用部分结果继续。
- 界面和进度日志必须保留“部分结果”标识。

### 6. 生成普通本地歌单

生成结果写入普通洛雪本地歌单，不绑定在线歌单的 `sourceListId`，避免同步动作覆盖用户后续补充或删减。

- 默认名称为“`<歌手名> - 全专辑`”。
- 写入前必须预览并确认。
- 同名本地歌单存在时默认不覆盖，由用户选择新建、合并或取消。

> 四平台批次的命名和同名规则由 [BIZ-20260809-03](BIZ-20260809-03-four-source-discography-playlist-strategy.md) 局部修订为固定的“`<输入歌手名> - 酷狗/qq/网易/酷我`”，同名提示后仍新建四个歌单；本节命名继续适用于原酷狗单来源流程的历史验收。

### 7. 下载继续由用户确认

生成歌单不自动开始下载。用户从结果页或本地歌单进入洛雪原生批量下载弹窗并选择音质。

- 自定义源不支持目标来源或音质时，不得把目录生成失败与下载不可用混为一谈。
- 不新增、内置或绕过洛雪现有音频 URL 来源机制。

### 8. 入口归入“工具”页面

第一阶段在洛雪侧边栏增加一个“工具”入口，并提供“专辑抓取”视图。后续文件夹整理和 FLAC 转 MP3 可以在独立 REQ 批准后加入同一入口，本需求不创建未实现的占位功能。

> 后续导航命名与页面拆分已由 [BIZ-20260806-02 专辑抓取与歌曲整理独立导航](BIZ-20260806-02-album-collection-and-song-organizer-navigation.md) 局部替代：现有入口改名为“专辑抓取”，歌曲整理使用独立同级入口。本决策的其他业务规则保持有效。

## 被比较的替代方案

### 方案 A：通过歌曲搜索拼装全集

不采用。搜索按相关性返回，无法证明完整分页，也容易混入同名歌手、翻唱、现场和其他专辑歌曲。

### 方案 B：获取歌手全部歌曲后按专辑 ID 过滤

不作为“完整专辑”的最终判定。该方案只可用于预填分组、发现异常或安排请求，不能替代任何一张专辑的详情结果。即使预填曲数与专辑声明曲数一致，也必须调用专辑详情并以详情曲目完成最终校验。

### 方案 C：只保留正式录音室专辑和 EP

第一阶段不采用。Provider 分类不一致，使用名称或不完整字段过滤会产生不可验证的遗漏。用户可以在预览中取消选择。

### 方案 D：自动合并多个来源

第一阶段不采用。跨来源歌曲 ID、专辑版本、曲目数量和发布日期语义不一致，需要独立的合并需求和验收标准。

### 方案 E：把结果伪装成在线同步歌单

不采用。当前同步逻辑会用平台歌单内容整体覆盖本地列表，不适合用户后续补缺和删减。

## 影响

### 正面

- 目录来源和完整性边界可解释、可测试。
- 最大限度复用洛雪现有音乐信息、歌单和下载能力。
- 避免跨平台模糊匹配造成的误删、误合并和重复下载。

### 代价

- 用户需要提供平台歌手 ID 或链接。
- 第一阶段只能使用酷狗；其他来源必须有等价专辑详情能力后才能接入。
- 平台目录本身有错误时，本功能只能报告，不能承诺全网校正。
- 目录中可能包含用户不想要的单曲、现场或重制版本，需要预览选择。

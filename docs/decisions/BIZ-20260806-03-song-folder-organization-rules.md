## 决策

### 1. 平台范围锁定为 Windows x64

- 歌曲整理首期只在 Windows x64 启用，并只构建、验证 Windows x64 安装包。
- Windows x86/arm64、Win7、Linux 和 macOS 隐藏“歌曲整理”入口。
- FFmpeg 随 Windows x64 安装包提供，不依赖系统安装，也不在运行时联网下载。
- 仓库既有其他平台打包脚本不在本需求中删除或重构。

### 2. 根目录默认跟随下载路径，也可切换为手动目录

- 页面不展示目录模式开关，提供“选择指定目录”和“使用下载目录”两个明确入口。
- 默认动态跟随当前下载路径；指定目录继续持久化，取消选择时保留原目录。
- 打开页面不自动扫描；成功切换目录后清空旧结果并自动扫描新目录。
- 根目录直属文件完全忽略；根目录的每个直接子目录均解释为歌手目录。

### 3. 固定“根目录 → 歌手 → 专辑”层级

- 歌手目录的直接子目录解释为专辑目录。
- 专辑内部的 `CD1`、`Disc 2` 等更深目录只递归统计，不作为独立专辑，也不单独重命名。
- 直接放在歌手目录中的 MP3/FLAC 只计入歌手总数，不虚构专辑。
- 空歌手目录保留，允许重命名为 `<歌手>（0首）`，永不自动删除。

### 4. 只完整解码 MP3 与 FLAC

- “可播放”必须完成全文件解码；扩展名、文件头、元数据或能开始播放均不能单独判定通过。
- 结果区分“可播放”“无法播放”“检查失败”和“不支持”。
- 解码确认数据损坏才属于“无法播放”；权限、占用、超时、文件变化和单文件进程异常属于“检查失败”。
- 其他格式不解码；歌手目录内所有非 MP3/FLAC 普通文件均作为不支持文件进入异常列表。

### 5. 数量按唯一物理 MP3/FLAC 计算

- `N首` 包含可播放、无法播放和检查失败的 MP3/FLAC。
- 重复硬链接只计一次；普通内容相同但文件身份不同的音频分别计数，不计算内容哈希。
- 硬链接保留路径优先选择可完整解码且扩展名匹配实际格式的 MP3/FLAC，再按层级更浅、路径更短、中文数字自然排序决定。
- 硬链接跨越多个歌手时整体跳过，任一歌手行操作都不得影响其他歌手目录。

### 6. 异常通过行状态与详情日志展示

页面不展示正常歌曲完整列表，也不提供独立异常卡或异常筛选；歌手行显示异常状态和数量，点击“查看详情”后在最近详情日志中展示以下异常：

- 无法播放或检查失败的 MP3/FLAC。
- 所有非 MP3/FLAC 普通文件。
- 重复硬链接。
- 符号链接和目录联接。
- 空目录。
- 清理、重命名或回滚失败结果。

### 7. 一键清理只使用已确认的完整扫描快照

- 清理通过单个歌手行发起，只作用于该行歌手。
- 清理范围为重复硬链接、所有非 MP3/FLAC、重解析点和清理后为空的非歌手目录。
- 清理前展示数量、大小、完整清单、硬链接保留路径及待清理路径，并进行二次确认。
- 所有目标只移入 Windows 回收站；回收站不可用时跳过，不得永久删除。
- 重解析点不跟随目标，只移除链接入口；无法证明只影响链接时跳过。
- 无法播放和检查失败的 MP3/FLAC 不自动删除、移动、修复或转码。
- 先处理文件和链接，再从最深层删除真正为空的目录；歌曲整理根目录和歌手目录永不删除。
- 清理完成后自动重新扫描。

### 8. 重命名与 Easy Music 保持一致

- 歌手：`<歌手>（N首）`。
- 专辑：`<专辑基础名> (N首)`。
- 只剥离末尾完全匹配的旧同类后缀，避免重复追加且不误删名称中间文本。
- 表格持续展示歌手目标名称，详情日志展示完整专辑预览；点击歌手行“重命名”后立即执行，不再弹出二次确认，但扫描本身绝不触发重命名。
- 操作粒度为单个歌手行，整体处理其全部专辑，不单独选择专辑。

### 9. 冲突和失败按歌手隔离

- 每个歌手执行前预检其自身及全部专辑目标；任一目标冲突会跳过整个歌手。
- 其他歌手行不受当前操作影响。
- 同一歌手先重命名专辑，再重命名歌手；中途失败立即停止并尽力回滚已执行步骤。
- 回滚不完整时必须报告最终真实路径，不得只展示原计划。
- 仍含未清理文件且没有 MP3/FLAC 的专辑不重命名，并阻止所属歌手重命名。

### 10. 扫描可取消，磁盘操作不可中途取消

- 只有最新完整扫描允许清理或重命名；取消、部分枚举和整体失败结果只允许查看。
- 目录枚举完整但个别音频“检查失败”时仍允许操作，该文件继续计入数量。
- 清理或重命名开始后不提供中途取消，避免主动制造半完成状态。
- 扫描快照不跨应用重启保存；重启后必须重新扫描。
- 页面路由切换期间保留当前结果、实时进度、任务监听和最近详情；任务不因离开页面而重启或中止。
- 同目录重扫取消或失败时保留旧结果供查看，但旧结果不得执行磁盘操作；根目录变化时立即清空旧结果。
- 操作完成后自动重新扫描，并保留上一次操作的成功、跳过、失败和回滚结果。

## 被比较的替代方案

### 方案 A：同时支持全部桌面平台

不采用。完整解码器的资源、许可证、包体积和打包路径需要逐平台验证；首期锁定 Windows x64 形成可验收闭环。

### 方案 B：检查文件头或元数据

不采用。合法头部不能证明文件中后段可播放。

### 方案 C：后缀只统计可播放歌曲

不采用。无法播放或暂时检查失败的 MP3/FLAC 仍真实存在于目录中，后缀应表达唯一物理支持音频数量。

### 方案 D：永久删除或回收站失败后降级永久删除

不采用。清理误选必须可恢复；不能因为目标磁盘不支持回收站而扩大数据影响。

### 方案 E：自动删除损坏音频或普通内容重复文件

不采用。解码兼容性和不同发行版都可能造成误判；只自动清理文件系统能明确证明的重复硬链接。

### 方案 F：扫描后自动重命名

不采用。用户必须先查看预览并主动点击“执行重命名”，只是执行时不再增加第二个弹窗。

### 方案 G：清理或重命名作用于全部歌手

不采用。所有磁盘修改只由单个歌手行发起并作用于该歌手，方便逐行核对并保护其他目录。

## 代价与风险

- 内置 FFmpeg 会增加 Windows x64 安装包体积，实施前必须核对许可证和二进制来源。
- 将所有非 MP3/FLAC 纳入清理可能包含歌词、封面和说明文件，因此必须完整预览、二次确认并使用回收站。
- Windows 回收站对网络共享或部分磁盘可能不可用；这类目标只能跳过。
- Windows 目录占用、大小写重命名和目标冲突仍可能导致部分歌手失败，需要逐步结果与回滚记录。
- 重解析点与硬链接必须通过文件系统身份和路径边界验证，不能依赖扩展名或页面字符串。

# 下载曲序命名与专辑目录策略

> `BIZ-20260811-06` 已将第 6 节的超长文件名规则细化为歌手名与歌曲名分别使用 `...` 省略、保留稳定消歧信息，并要求最终名称为下载发布与校验内部后缀预留 Windows 单段空间。原有曲序、目录、路径固化和既有文件不移动规则继续有效。

## 决策问题

用户已经明确要求新增“曲序. 艺术家 - 歌曲名”命名方式，并支持按歌手和专辑目录保存。仍需固定曲序来源、一级目录归属、默认值、目录模式冲突、元数据缺失、多碟专辑和既有任务兼容规则，否则合作曲目可能按专辑艺术家拆散，相同歌曲也可能因下载入口或设置状态不同得到不同路径。

2026-08-06 用户进一步确认参考 `easy-music` 的下载落盘语义：歌手全专辑歌单使用“抓取目标歌手”作为一级目录，而不是专辑艺术家；普通入口没有该上下文时再保守回退。本次不增加 `(N首)` 目录后缀，该后缀属于独立的下载后文件夹整理能力。

## 推荐决策

### 1. 两项能力均由用户主动选择

- 文件命名方式新增“曲序. 艺术家 - 歌曲名”，但现有默认值“歌名 - 歌手”保持不变。
- 下载目录增加“按歌手/专辑”组织方式，但升级后默认仍保持现有目录行为。
- 两项设置可以独立选择：启用专辑目录不强制切换文件命名方式，选择曲序命名也不强制启用专辑目录。
- 新设置只影响确认后新建的下载任务，不移动既有文件，也不重算已经持久化的任务路径。

理由：用户要求的是“增加选项”，不应在升级后批量改变已有用户的磁盘布局。

### 2. 曲序只使用专辑内顺序

输出格式为：

```text
<曲序>. <艺术家> - <歌曲名>.<扩展名>
```

- 曲序来自 Provider 的可靠专辑曲序；没有独立曲序字段但已经取得完整专辑详情时，使用详情的稳定顺序。
- 文件名中的“艺术家”使用曲目级艺术家；一级目录按“抓取目标歌手 → 专辑艺术家 → 曲目艺术家”回退，使歌手全专辑中的合作曲仍归入用户确认的抓取目标歌手。
- 曲序至少两位，专辑超过 99 首时按总曲数自然扩展位数。
- 不使用当前歌单位置、用户勾选顺序、下载队列位置或任务完成顺序。
- 首期多碟专辑按专辑详情中的全局顺序连续编号，不增加碟号前缀或碟号子目录。
- 缺少可靠曲序时，不伪造 `00` 或队列序号；文件名回退为“艺术家 - 歌曲名”，并在本次批量操作中汇总提示一次。

### 3. 目录组织方式改为互斥选择

推荐把目录组织表达为一个互斥选项，而不是叠加多个布尔开关：

1. 不分组：沿用下载根目录。
2. 按歌单名：沿用当前行为。
3. 按歌手/专辑：使用本需求的新结构。

选择“按歌手/专辑”时，不再额外嵌套歌单名，目标目录为：

```text
<下载根目录>\<歌单归属歌手>\<YYYY-MM-DD 专辑名>\
```

最终文件名仍由独立的文件命名方式决定。两项新设置同时启用时，完整路径例如：

```text
C:\Users\蔡徐坤\2017-12-15 I Wanna Get Love\01. 蔡徐坤 - I Wanna Get Love.flac
```

理由：`<歌单>/<歌手>/<专辑>` 会让同一专辑因下载入口不同产生多个副本；互斥选项也能避免两个开关同时启用时的优先级歧义。歌手全专辑入口应沿用 `easy-music` 的歌单归属语义，使合作曲、合唱曲和不同专辑艺术家仍收拢到用户抓取的目标歌手目录。

### 4. 目录优先使用歌单归属歌手

- 歌手全专辑计划必须把已确认的抓取目标歌手写入歌曲元数据，不能从可重命名的歌单名称反向截取。
- 一级目录按“抓取目标歌手 → 专辑艺术家 → 曲目艺术家”依次选择；普通搜索和普通歌单没有抓取目标歌手时自然从专辑艺术家开始回退。
- 专辑目录使用有效完整发行日期和专辑名，日期格式统一为 `YYYY-MM-DD`。
- 日期缺失、非法或只有年/月精度时，省略日期前缀，仅使用专辑名，不补零、不猜测具体日期。
- 专辑名缺失时，不创建“未知专辑”等虚构目录，文件直接保存到艺术家目录。
- 艺术家也缺失时，文件保存到下载根目录。
- 每次批量创建任务只汇总提示一次回退情况，避免逐曲弹出通知。
- 下载阶段不添加 `(N首)` 后缀，也不在任务完成后移动目录；若后续需要按实际文件数重命名，应作为独立文件夹整理需求设计和确认。

### 5. 适用于全部原生下载入口

用户选择新格式或新目录方式后，它适用于单曲下载、普通歌单批量下载和全专辑歌单批量下载。完整元数据得到完整结构；元数据不足则按上一条保守回退。

不把本功能限制在“工具 → 专辑抓取”，因为它位于全局下载设置中；也不因此扩大歌手全专辑功能的 Provider 范围。

### 6. 路径安全沿用统一规则并补齐目录段校验

- 艺术家、专辑和文件名分别清洗，不允许动态文本注入路径分隔符或逃逸下载根目录。
- 处理 Windows 非法字符、保留名称、尾随点/空格和路径长度。
- 截断时保留扩展名，并尽量保留曲序和可辨识文本。
- 同名冲突沿用原生下载的既有处理语义；若现有语义不足，DEV 必须明确补充，不能静默覆盖。

### 7. 任务创建时固化最终结果

- 文件名、目录和回退原因在下载任务创建时解析并持久化。
- 应用重启、暂停恢复或失败重试继续使用任务中已有路径，不根据最新设置重新计算。
- 歌词等关联文件跟随音频目录，并使用音频文件的最终基名。
- 曲序格式属于下载文件名语义；当前复用通用文件名 formatter 的播放器标题、复制歌曲名等非下载场景必须保持原有可读行为，不能显示未替换模板或伪造曲序。

## 被比较的替代方案

### 方案 A：使用歌单或下载队列序号

不采用。同一专辑从不同歌单下载会产生不同编号，并发任务顺序也不稳定，不能表达专辑曲序。

### 方案 B：同时启用“按歌单”和“按专辑”并逐级嵌套

不采用。同一专辑会按来源歌单重复保存，且两个开关的优先级难以解释。

### 方案 C：缺少日期时使用 `0000-00-00`，缺少曲序时使用 `00`

不采用。占位值会伪装成真实元数据，并把大量文件聚集到误导性的排序位置。

### 方案 D：缺少专辑元数据时阻止下载

不采用。新能力是文件组织增强，不应破坏原生下载可用性；使用保守回退并汇总提示即可。

### 方案 E：下载完成后扫描并重排已有文件

不采用。这会扩大为文件迁移工具，带来覆盖、跨盘移动和任务记录失效风险。

## 影响

### 正面

- 完整专辑在文件系统中能够按曲序稳定排序，并按抓取目标歌手、发布日期和专辑归档。
- 默认行为不变，用户可以逐步启用新能力。
- 所有原生下载入口共享一套命名与路径规则。
- 元数据不足时不伪造日期和曲序，结果可解释。

### 代价

- 通用歌曲或下载上下文需要补充抓取目标歌手、专辑艺术家、发行日期和曲序数据流。
- 当前“按歌单名分组”布尔设置需要兼容迁移为互斥目录组织方式。
- 普通搜索结果和旧歌单可能只能得到回退路径。
- 多碟专辑首期只提供连续曲序，不表达独立碟号。

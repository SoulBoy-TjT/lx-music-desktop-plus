# 完整 FLAC 仅对末帧后有界尾随数据执行无损规范化

## 关联文档

- 关联缺陷：[BUG-20260811-06 完整 FLAC 因末帧后尾随数据被严格校验拒绝](../bugs/BUG-20260811-06-valid-flac-rejected-for-trailing-data.md)
- 候选消歧缺陷：[BUG-20260811-08 完整 FLAC 因相邻末帧 CRC 候选被歧义保护误拒](../bugs/BUG-20260811-08-flac-terminal-frame-boundary-ambiguity.md)
- 技术方案：[DEV-20260811-01 下载真实格式校验与元数据发布技术方案](../designs/DEV-20260811-01-download-actual-format-publication.md)

## 决策

1. 严格完整解码仍是最终发布的默认边界；不得全局忽略 FFmpeg 错误，也不得仅凭“可以播放”或时长看似正常发布文件。
2. 只有同时满足以下证据的 FLAC 才能进入尾随数据规范化候选：容器和 STREAMINFO 合法；从首帧到最终音频帧均可解码；实际解码样本数与 STREAMINFO 声明完全一致；最终音频帧结构和 CRC 有效；异常字节全部位于该最终帧之后。
3. 规范化只能删除已经定位到最终合法音频帧之后的非空、小范围有界尾随字节，不得重编码音频帧、补造样本、修改音频参数或根据时长估算截断位置。实现必须设置明确的小范围上限；超过上限继续按损坏内容拒绝。
4. 规范化结果必须重新执行与普通下载相同的严格完整解码及格式、样本数校验；复验全部通过后才能进入元数据写入和不覆盖发布，复验失败不得留下成品。
5. 中段无效数据、样本数不足或超出、任一音频帧/CRC 错误、无法可靠定位最终帧、未知格式、容器与 codec 冲突以及超出尾随上限的内容仍然拒绝，不得借此规则降级校验。
6. 用户可见结果应保持真实 FLAC，不把完成无损规范化的文件误报为 MP3 降级；若规范化失败，继续展示可定位的校验失败原因。
7. 末帧附近出现多个 CRC-valid 边界不单独构成放行或拒绝依据。实现可以在明确数量上限内按边界升序逐一复验；只有严格完整解码成功、声明样本数一致，且 canonical PCM 与原始失败解码已经输出的完整音频内容一致时，才采用首个匹配边界。候选超限或全部复验失败继续拒绝，不按最早、最晚、时长或可播放现象猜测。

## 对既有决策的局部修订

本决策只修订 `BIZ-20260811-01`“决策”第 5 条中“损坏内容”的分类边界：已由完整样本数、最终帧结构与 CRC 共同证明音频主体完整，且异常仅存在于最终帧后的有界尾随数据，不再直接归为不可发布损坏内容，而是允许先无损规范化再严格复验。`BIZ-20260811-01` 的真实格式发布、明确降级、不覆盖和不处理既有文件等其余条款保持不变，原决策状态保持 `accepted`。

## 确认记录

用户在看到具体判定依据后于 2026-08-11 明确要求修复，接受“只删除最终合法音频帧后的有界尾随数据，并在严格复验通过后发布”的边界；随后针对《怜心（伴奏）》明确要求增强末帧边界判定，接受在相邻 CRC-valid 候选间以严格解码、声明样本数和 canonical PCM 一致性选取首个匹配边界。本决策状态保持 `accepted`。

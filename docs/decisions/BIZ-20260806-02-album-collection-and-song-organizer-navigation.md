# 专辑抓取与歌曲整理独立导航

## 关联文档

- 来源需求：[REQ-20260806-02 歌曲文件夹整理与音频可播放性检查](../requirements/REQ-20260806-02-song-folder-organizer.md)
- 被局部修订的决策：[BIZ-20260805-01 歌手专辑目录口径与来源策略](BIZ-20260805-01-discography-scope-and-source.md)
- 技术方案：[DEV-20260806-02 歌曲文件夹整理技术方案](../designs/DEV-20260806-02-song-folder-organizer.md)

## 决策

1. 现有侧边栏“工具”入口改名为“专辑抓取”，其页面只表达歌手专辑目录获取与歌单生成能力。
2. 新增同级独立入口“歌曲整理”，不作为专辑抓取页面内的标签、卡片或子功能。
3. 两个入口使用独立的 route name、view 目录、页面状态和国际化命名空间。
4. 旧 `/tools` 路由只允许作为兼容重定向，不再作为面向用户的功能名称。

> 2026-08-09 起，导航图标由 [BIZ-20260809-02](BIZ-20260809-02-tool-input-directory-and-icons.md) 补充约束：专辑抓取、歌曲整理和 FLAC 转 MP3 必须使用三个不同且与现有侧边栏一致的单色图标。

本决策仅修订 [BIZ-20260805-01](BIZ-20260805-01-discography-scope-and-source.md) 第 8 节“入口归入工具页面”的导航安排，不改变该决策中的 Provider、专辑范围、去重、完整性和下载确认规则。由于是局部修订，使用 `amends` 而不是表示完整替代的 `supersedes`。

## 理由

- 专辑抓取是在线 Provider 目录获取流程，歌曲整理是本地磁盘扫描与重命名流程，数据来源、风险和状态机不同。
- 独立页面能避免把长时间音频校验状态与专辑抓取快照混在同一个组件中。
- “专辑抓取”比“工具”更准确，能够让侧边栏入口直接表达当前已有功能。

## 影响

- 现有 `Tools` route/view/翻译键需要迁移或提供兼容别名。
- 侧边栏新增一个入口，需要为窄窗口、键盘导航和 active route 状态做回归验证。
- 已有专辑抓取业务逻辑不因页面改名而重构，当前未完成的验收项继续保留。

## 确认依据

用户于 2026-08-06 明确要求歌曲整理界面与现有工具界面独立，并将工具名称改为“专辑抓取”，因此本决策直接记录为 `accepted`。功能代码仍须等待 REQ 与技术方案整体确认后实施。

# 超长歌手与歌曲字段分别省略并预留下载内部文件名空间

## 决策问题

用户实际下载两首长歌手列表的合唱曲时，最终可见文件名尚在原下载目标预算内，但发布校验追加内部后缀后超过 Windows 单段文件名上限，任务在内容已经下载完整后以 `ENOENT` 失败。现有实现还会从整个基名末尾统一截断，使长歌手列表挤占歌曲名，用户无法从结果中辨认歌曲。

用户于 2026-08-11 明确确认：歌曲名过长或歌手名过长时可以在合适位置省略，例如“`01. 韦唯、周深、萧敬腾、郁可唯、王祖蓝、李亚男... - 111111111111111...`”，不要求保留全部原始文本。

## 决策

1. 包含歌手和歌曲名的下载文件名不得再把整个基名作为一个不可分字段从末尾统一截断；超出预算时分别缩短过长的歌手名和歌曲名。
2. 结构化曲序格式必须优先保留曲序前缀、歌手与歌曲名的字段顺序、` - ` 分隔符和真实扩展名；歌手和歌曲名同时存在时，两者都应保留可辨识片段。
3. 被缩短的字段在字符边界处截断并使用半角 `...` 表示省略；没有超出预算的字段不追加省略号。
4. 截断结果必须稳定、可复现，并保留稳定短摘要或等价消歧信息，避免不同长名称因前缀相同而静默收敛到同一目标；已有文件与同批任务仍遵守不覆盖和冲突提示语义。
5. 用户可见最终音频名称必须为下载发布、格式校验、FLAC 尾随规范化和所有权文件等内部文件名预留最长已知后缀空间；任何阶段都不得先接受一个随后必然超过 Windows 单段上限的目标名称。
6. 内部后缀发生变化时，最长后缀预算必须与下载目标限制同步维护并由自动化覆盖，不能依赖 Windows 长路径开关绕过单段文件名限制。
7. 新规则只影响修复后新建的下载任务。已持久化任务继续使用其固化路径，不自动重算、移动或重命名既有文件；失败任务需要按现有交互重新创建后才能使用新名称。

## 对既有决策的局部修订

本决策细化 `BIZ-20260806-01` 第 6 节“截断时保留扩展名，并尽量保留曲序和可辨识文本”：可辨识文本明确包括歌手名与歌曲名两个语义字段，字段级省略优先于整个基名末尾截断；路径预算同时覆盖用户可见文件和下载发布链的内部文件名。本决策不改变原有曲序来源、目录组织、任务路径固化、不覆盖及既有文件不移动规则。

## 确认记录

用户于 2026-08-11 明确提出并确认超长歌手名或歌曲名可以在合适位置使用 `...` 省略。本决策直接记录为 `accepted`；具体修复和验证由 `BUG-20260811-07` 跟踪。

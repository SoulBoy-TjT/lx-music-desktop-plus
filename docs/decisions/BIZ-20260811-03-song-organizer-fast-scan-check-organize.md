## 决策

### 1. 快速扫描只建立目录统计快照

- 首次启动、根目录变化及用户重新加载时先完成目录枚举、扩展名分类、稳定物理文件身份、歌手/专辑计数、目录冲突和静态安全检查。
- 快速扫描不启动 FFmpeg，不把扩展名匹配等同于可播放，也不产生“完整音频已检查”的结论。
- 快速统计完成即可展示歌手、歌曲数和按当前目录事实可计算的目标名称；深度音频状态明确标为“未检查”或等价状态。
- 快速统计是可取消、可随时重新加载的只读操作；路由切换继续保留当前会话结果。
- 一级歌手目录发现必须排除 FLAC Converter 自动输出目录：只按严格成对括号和 Windows 大小写不敏感规则识别 `<base> MP3`、`<base> MP3（N首）`、`<base> MP3(N首)`；不得使用任意 `contains` 误伤名称中正常包含 `MP3` 的真实歌手。快速统计与检查使用同一排除函数。

### 2. “清理”改为“检查”

- 原行级“清理”按钮改名为“检查”，负责对所选歌手当前快速快照中的唯一 MP3/FLAC 执行完整 FFmpeg 解码，并复核清理候选、目录能力及操作阻塞。
- 检查成功形成带来源快速快照版本与文件身份的深度验证快照；取消、整体失败或根目录变化不产生可执行快照。
- 单文件无法播放、检查失败和其他异常继续形成可定位详情，不自动删除或修复音频。

### 3. 原清理与重命名合并为“整理”

- “整理”只能基于同一根目录、同一歌手且仍有效的最近一次深度验证快照执行；无有效检查结果时禁用并提示先检查。
- 整理先按原安全规则清理已经确认且仍合格的重复硬链接、非 MP3/FLAC、重解析点和空目录，再基于清理后的真实结果执行专辑与歌手数量后缀重命名。
- 清理仍需在整理前展示完整范围并获得二次确认；执行时安全复核只能缩小已确认范围，不能加入未确认目标。
- 任一阶段失败必须停止不安全的后续步骤，并保留成功、跳过、失败和回滚结果供人工核查；不得用成功提示覆盖部分失败。

### 4. 操作后只做一次不解码的轻量刷新

- 整理完成、部分失败或回滚后不得自动启动全根目录 FFmpeg 扫描。
- 整理达到可恢复终态后允许且必须执行一次不调用 FFmpeg 的轻量目录刷新，读取磁盘最终真实路径与数量；页面不能继续显示改名前的旧目录。
- Main 结合操作结果和轻量刷新更新当前歌手路径、计数、目标名称和快照有效性；无法证明准确的字段明确标为待重新检查。
- 整理导致音频集合、文件身份或受保护状态变化时，深度验证快照失效并提示重新“检查”；仅路径安全改名且引用同步成功时可保留能够证明仍有效的检查结论。
- 用户可随时重新加载快速统计；重新检查由用户显式触发。

### 5. 退出保护保持分层

- 快速扫描和检查属于可取消的只读任务，应用关闭时取消并等待 FFmpeg 子进程退出。
- 整理包含清理、重命名、路径引用同步和回滚，执行期间继续阻止正常退出，直到达到可恢复终态。

- 修订 `BIZ-20260808-01` 第 1、2 节：Main 启动预扫描保留，但改为快速扫描；页面提供可随时重新加载快速统计的入口。
- 修订 `BIZ-20260810-04` 第 7 条：完整解码约束只适用于用户发起的“检查”，不再要求每次快速扫描或整理后刷新都完整解码。
- 未被本决策修改的回收站、硬链接、重解析点、下载/播放保护、危险目录、操作日志、路径同步、失败核查和不覆盖规则继续有效。

## 确认记录

快速显示目录统计、以“检查”执行完整音频校验、把原清理与重命名合并为“整理”、操作后只做一次不解码轻量刷新以及分层退出保护，均由用户于 2026-08-11 明确提出并确认，状态为 `accepted`。

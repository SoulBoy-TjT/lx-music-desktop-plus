## 修订范围

本决策修订 `BIZ-20260807-03` 第 1、2、4、6、7、8 节中的启动时机、目录控件和页面排版，并修订 `BIZ-20260807-02` 第 4、9 节中未完成下载对清理操作的阻塞粒度。Windows x64、完整解码、无跨扫描缓存、回收站、硬链接、危险根目录、恢复日志和路径同步规则继续有效。

固定扫描状态、双列审计带和固定最近详情由 `BIZ-20260808-02` 继续修订；本决策的后台预扫描、清理隔离和其余安全规则保持有效。

## 决策

### 1. 扫描在应用启动后于 Main 后台开始

- 应用设置和数据库完成初始化、歌曲整理 IPC 完成注册后，Main 立即对当前歌曲整理根目录发起一次无缓存扫描，不等待用户进入歌曲整理页面。
- 新安装和未选择自定义目录的用户默认使用当前下载目录；用户已经明确选择并持久化的指定目录继续生效，不在升级或重启时强制覆盖。
- 页面进入时读取 Main 的当前扫描状态：后台任务仍在进行时接续显示其进度和取消入口，已经完成时直接展示最新完整快照，不重复启动扫描。
- 启动预扫描失败只记录扫描状态和原因，不阻止应用主窗口启动，也不降低危险根目录、FFmpeg 和目录能力校验。
- 启动预扫描、目录变化、下载占用变化、清理后重扫和重命名后重扫继续共享 Main 单任务语义；Renderer 只接管运行态，不再为同一配置变化重复发起扫描。新任务开始时安全取消旧扫描，旧任务不得覆盖状态。

### 2. 页面不再提供顶部“扫描”和“打开目录”

- 标题区只保留“歌曲整理”和简短说明，不放置全局操作按钮。
- 原“父目录”统一改名为“扫描目录”，目录行只保留当前路径、“选择指定目录”和“使用下载目录”。
- 不再提供独立手动“扫描”按钮；应用启动、成功选择指定目录、点击“使用下载目录”、下载目录变化以及磁盘操作完成都会触发扫描。
- 顶部“打开目录”移除；歌手行“打开文件夹”继续在资源管理器中定位并选中歌手目录。

### 3. 未完成下载只阻塞重命名和实际占用项

- 未完成下载或下载后处理继续阻塞所属歌手的重命名，防止目录移动破坏正在使用的路径。
- 歌手存在未完成下载时，不再整体禁用该行清理；扫描快照中可安全清理的非 MP3/FLAC（包括 `.lrc`）仍进入预览和二次确认。
- 当前播放文件、实际下载目标、其同基名 `.lrc`、两者的 `.lxmtemp`/`.lxmbackup`、音频的 `.lxcover.*`、上述目标的待清理祖先目录、发生变化的文件和不可证明仍符合计划的目标继续逐项跳过并记录原因；其他清理目标不受牵连。
- 用户确认后，执行范围只能是“已确认预览路径”与“执行时最新安全路径”的交集，不得因下载状态变化自动扩大清理范围。
- 行状态可以同时显示“待清理”和“重命名受阻”：前者表示存在可清理项，后者准确说明下载占用只阻止重命名；部分目标不可清理时使用“清理受阻”，只有两类操作都不可执行时才使用泛化“操作受阻”。

### 4. 工作区改为克制的目录审计布局

- 标题、扫描目录、扫描状态、最近详情和歌手表格继续位于同一工作区，但减少大面积主色背景和重复边框。
- “扫描目录”使用紧凑目录轨道：标签、可省略路径和两个目录按钮保持同一视觉组；路径使用高可读的工具型字形，不使用整条高饱和背景。
- 扫描状态与最近详情组成桌面端双列“审计带”：左侧显示结果摘要或扫描进度，右侧显示最近详情；窄窗口自动纵向堆叠。
- 最近详情限制高度并内部滚动，表格继续占据主要可用空间；无详情时不渲染空详情容器。
- 状态标签改为低饱和描边/浅提示，只在进度、危险和当前可执行动作上使用主题主色、警告色和错误色；表格行、表头和操作按钮保持 LX Music 既有组件风格。

## 代价与风险

- 启动即完整解码会增加应用启动后的后台磁盘与 CPU 占用，但不阻塞窗口创建；每次扫描仍不使用跨次缓存。
- 页面可能在后台扫描中途被打开，因此 Main 必须提供可查询、可订阅的扫描状态，不能只依赖发起扫描的 Renderer Promise。
- 放宽歌手级清理阻塞后，执行前逐项目标校验成为必要安全边界；任何无法确认未被下载占用的目标必须跳过。
- 双列审计带需要在窄窗口回落为单列，避免详情区挤压五列表格。

## 确认记录

启动后台预扫描、移除顶部“扫描/打开目录”、“父目录”改为“扫描目录”、默认使用下载目录、允许安全清理歌词文件以及重新优化工作区排版，均由用户于 2026-08-08 明确提出，本决策直接记录为 `accepted`。

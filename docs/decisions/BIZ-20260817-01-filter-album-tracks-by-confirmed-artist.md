## 决策问题

既有口径会把 Provider 专辑详情中的全部曲目写入来源歌单，即使某首歌曲的曲目艺术家不包含本次已经确认的歌手。混合原声、精选或多人专辑因此可能把完全由其他歌手演唱的歌曲纳入结果。

用户要求参照 `easy-music` 的歌单抓取逻辑：完整取得专辑详情后，只把目标歌手实际参与的曲目组装进来源歌单。例如输入并确认“蔡徐坤”后，联合艺术家中存在“蔡徐坤”这一独立艺术家项的歌曲保留，不匹配的歌曲排除。

## 决策

### 1. 完整详情校验先于歌手参与筛选

各 Provider adapter 继续完整获取并严格映射逐专辑详情。专辑声明曲数、详情返回总数、合法字段、专辑归属、重复 ID 和分页完整性仍以筛选前的详情结果校验；主动排除非目标歌手歌曲不是 Provider 缺失，不得因此产生 `album_incomplete` 或把来源降为 `partial`。

### 2. 来源组装只保留已确认歌手参与的歌曲

单来源 plan 和 apply 共用同一个来源组装函数，在稳定歌曲 ID 去重之前执行歌手参与筛选。匹配目标使用该来源已经由用户确认的 `ArtistRef.name`，不使用未经确认的跨平台身份，也不把曲目原始 `singer` 覆盖为目标歌手。

筛选后的歌曲数组用于：

- 来源摘要中的歌曲计数。
- 来源内稳定歌曲 ID 去重及去重核查。
- 歌单名称中的最终 `N`。
- 实际提交到本地歌单的歌曲数组。

某张专辑没有目标歌手参与曲目时贡献 0 首，但其完整详情仍可作为内部完整性证据；单独出现这种情况不构成异常。某来源筛选后最终为 0 首时，沿用既有 `empty_catalog` 阻断，不允许创建空歌单。

### 3. 联合艺术家按独立名称项精确匹配

参照 `easy-music`，曲目 `singer` 先按 `/`、`、`、`,`、`，`、`;`、`；`、`|`、`&`、`＆`、`+`，以及两侧带空格的 `feat`、`ft`、`with`、`x` 拆分。目标和每个候选项执行 NFKC、大小写及常见空白/标点规范化后，要求至少一个独立项完全相等。

中文名允许显示名携带连续拉丁别名前后缀：双方移除拉丁字母和数字后，剩余中文完全相等时也视为同一歌手。因此“蔡徐坤”“周杰伦、蔡徐坤”“KUN蔡徐坤”可以匹配“蔡徐坤”，但“蔡徐坤工作室”和普通任意子串不能匹配。

### 4. 曲序不因筛选重新压缩

保留歌曲继续使用 Provider 详情中的可靠曲序或既有稳定位置回退；排除中间曲目后允许保留曲序空档，不按筛选后的数组位置重新编号。`trackTotal` 继续表达已校验的专辑详情总曲数，不伪造为筛选后数量。

## 被修订内容

- 修订 `BIZ-20260805-01` 第 4 节及确认项中“专辑详情全部曲目不按目标歌手过滤”的口径；完整详情仍必须获取和校验，但最终来源歌单只组装已确认歌手参与的歌曲。
- 修订 `BIZ-20260809-03` 第 3 节关于来源快照歌曲集合的口径；四来源仍各自独立，只在来源内部按本决策筛选，不建立跨来源歌手映射。
- 既有来源选择、身份确认、分页、去重、部分结果、批量补偿、普通本地歌单和不自动下载规则继续有效。

## 验收边界

- 合作曲只要联合艺术家中包含目标歌手独立项就保留。
- 其他歌手独唱、缺少可匹配艺术家的曲目和仅含目标名称子串的其他身份排除。
- 筛选前专辑详情完整时，筛选导致的歌曲数减少不产生完整性错误。
- plan 预览计数、apply 重新组装、歌单名称数量和实际提交数组保持一致。
- 不新增数据库迁移、生产依赖或第二套歌单写入链路。

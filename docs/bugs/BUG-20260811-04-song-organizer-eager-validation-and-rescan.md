# 歌曲整理首次完整解码与操作后重扫导致结果迟缓

## 关联文档

- 当日进度：[PROG-20260811](../progress/PROG-20260811.md)

## 诊断证据

当前 605 首、约 16.26 GiB 的只读扫描总耗时约 66.61 秒，其中目录发现约 0.10 秒，605 次 FFmpeg 完整解码约 66.50 秒，占比超过 99%。重命名本身只需毫秒至百毫秒级，但完成后同步等待一次全量解码重扫，导致用户感知为重命名缓慢。

## 期望行为

- 首次和重新加载先返回不运行 FFmpeg 的快速目录统计。
- 完整解码由用户点击“检查”显式执行并形成深度验证快照。
- 原清理和重命名合并为“整理”，只使用最近有效检查结果。
- 整理后执行一次不调用 FFmpeg 的轻量目录刷新，更新真实路径与数量，并明确标记待重新检查；不自动完整解码。
- 快速统计和检查都严格排除 FLAC Converter 的无数量/中英文数量后缀输出目录，不把任意包含 `MP3` 的真实歌手名误排除。

## 修复与验证证据

- 启动、目录切换和“重新加载”改为 `scanArtistsQuick` 快速统计，不调用音频 validator；“检查”按单个歌手建立带文件身份指纹的深度验证快照，文件新增、删除、替换、大小或修改时间变化都会令快照失效。
- 原“清理”“重命名”合并为“整理”，从加锁到清理、重新计数、重命名和引用同步均保持同一操作边界；终态只执行一次不调用 FFmpeg 的轻量刷新，不再自动全量解码。
- 快速统计与检查共用严格输出目录排除规则，Windows 大小写不敏感排除 `<base> MP3`、`<base> MP3（N首）`、`<base> MP3(N首)`，不会用任意包含关系误伤真实歌手名。
- 真实用户目录只读快速统计得到 406 首、78 个专辑、2 个有效歌手，耗时约 120.6 ms、validator 调用 0 次，并确认 `刘雨昕 MP3（199首）` 未进入歌手列表。定向测试 22 个文件、140 项全部通过，全专题 52 个文件通过、1 个文件跳过，419 项通过、1 项跳过。
- 安装包静态核验确认 Main/Renderer 包含快速扫描、检查、整理、重新加载、详情和真实步骤进度实现；旧 `cleanup_preview`、`cleanup_apply`、`rename_apply` 生产入口均不存在。

缺陷状态收口为 `fixed`。尚未运行安装器，也未在真实 Electron 中执行检查、整理、回收站清理、重命名、轻量刷新和退出保护，因此不标记为 `verified`。

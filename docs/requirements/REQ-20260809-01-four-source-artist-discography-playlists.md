## 背景

`REQ-20260805-01` 已完成酷狗单来源的歌手确认、完整专辑目录快照、预览选择和普通本地歌单写入闭环，但其范围明确限定为一次一个来源，网易云、QQ 音乐和酷我音乐留作后续扩展。

用户现确认将专辑抓取入口改为四平台能力：每次只输入一个歌手名称，抓取前可从酷狗、QQ 音乐、网易云音乐和酷我音乐中选择一至四个来源，系统为所选来源确认歌手并取得互相独立的目录快照；抓取后再从合格快照中选择本次要生成的来源歌单。两个阶段默认全选可用来源。

## 目标

用户输入一次歌手名称后，系统能够：

1. 在用户选中的 `kg`、`tx`、`wy`、`kw` 来源中执行严格名称解析；网易除完整展示名外允许严格汉字/拉丁双脚本完整名称段匹配，不使用任意模糊匹配。
2. 每个所选平台按 Provider 原始稳定顺序解析首个严格合法结果；等待身份解析全部抵达，只在至少一个来源成功时用一个确认界面展示成功身份子集的 Provider 原名和 ID。
3. 统一确认后并行取得成功身份子集各自的全部歌手专辑及逐专辑完整详情；先校验完整详情，再只把各来源已确认歌手参与的曲目纳入来源组装。身份解析失败来源保留 `failed`，不阻断成功来源形成互相独立的目录快照。
4. 在一个预览页面中展示已抓取平台的来源摘要、来源级完整性说明，以及实际发生去重时的结构化核查信息。
5. 符合写入条件时，按用户抓取后勾选的非空来源子集创建固定命名的普通本地歌单。
6. 保留现有原生批量下载入口，不在抓取或建歌单后自动下载。

术语以仓库根目录 [CONTEXT.md](../../CONTEXT.md) 为准。

## 用户场景

### 场景一：一次预览四个平台

用户在“专辑抓取”页面输入“蔡徐坤”，抓取来源初始默认四个平台全部勾选，也可以只保留需要的平台。系统只在所选来源按 Provider 原始稳定顺序选择首个严格合法结果；网易额外支持汉字/拉丁双脚本完整名称段。系统等待所有所选来源解析抵达；若至少一个来源成功，则在一个确认界面中展示成功身份子集的来源、头像、Provider 完整名称和来源内 ID。用户确认后，成功身份子集可以并行抓取；解析失败来源保留 `failed` 摘要但不阻断。页面按来源展示互不合并的摘要，不展示逐专辑明细或选择，并自动把每个成功来源的全部合法专辑纳入该来源快照。

例如输入“刘雨昕”时，网易展示名“刘雨昕XIN LIU”可按汉字与拉丁字母脚本边界形成完整别名段匹配。若 Provider 原始结果中该艺人在前、另一个完全同名艺人在后，系统必须选择前者，不能跨越顺序全局优先完全同名类型；统一确认展示最终所选 Provider 完整名称、ID、头像和声明专辑数，用户可确认或取消。输入“刘雨”等不完整子串不得匹配。

### 场景二：一次创建四个来源歌单

抓取完成后，全部合格来源默认勾选为生成目标，用户也可只保留任意非空子集。若四个平台均被选中，系统新建以下四个普通本地歌单：

- `蔡徐坤-酷狗-<Nkg>首`
- `蔡徐坤-qq-<Ntx>首`
- `蔡徐坤-网易-<Nwy>首`
- `蔡徐坤-酷我-<Nkw>首`

实际生成的每个歌单只包含对应来源完整专辑详情中、曲目艺术家匹配该来源已确认歌手的歌曲，并在来源内按稳定 `track.id` 去重；完全由其他歌手演唱的歌曲先排除，每个 `N` 等于筛选并去重后实际提交歌曲数，不同来源之间不合并或去重。例如酷狗实际提交 77 首时名称为“`蔡徐坤-酷狗-77首`”。未勾选的合格来源保留预览但不创建歌单。

### 场景三：部分结果和来源失败

某个来源在身份解析阶段失败时，系统等待其他所选来源解析完成，只对成功身份子集统一确认并继续抓取；失败来源保留 `failed`。若没有任何身份解析成功，则不弹确认，批次直接阻断。目录为 `partial` 但经歌手参与筛选及来源内去重后仍有合法歌曲时，完整性说明继续展示缺失边界，该来源无需额外确认即可参与生成选择。来源为 `failed`、`cancelled`，或其全部合法专辑经筛选和去重后最终没有合法歌曲时，该来源不可勾选并显示原因，但不阻断其他合格来源组成非空生成子集。重试会丢弃当前快照并按当时的抓取来源选择重新执行新批次。

### 场景四：批量写入失败

若本次选中生成子集中的任一个歌单创建或加歌失败，系统撤销本次已经创建的全部新歌单。由于本地歌单写入不是数据库事务，该撤销为尽力补偿；补偿失败时必须报告残留歌单的名称和 ID，不能显示批量创建成功。未选来源不属于本次写入或回滚边界。

### 场景五：切换页面后继续使用已抓取快照

目录抓取完成后，用户切换到搜索、歌单、下载或其他路由，再返回“专辑抓取”页面。系统继续展示本次输入、同一 `batchId`、抓取来源选择、已抓取来源摘要、生成来源选择、来源级完整性说明、精简去重核查和 apply 结果，不重新请求 Provider。只有用户显式重新获取时才用新批次替换当前结果；刷新或重启应用后不恢复抓取快照，抓取来源恢复默认全选。

## 范围

### 包含

- 专辑抓取入口每次只接受一个歌手名称；不接受来源 ID、链接，但提供 `kg`、`tx`、`wy`、`kw` 抓取来源复选项并默认全部选中。
- 每批处理用户选择的一至四个平台；零个抓取来源时在请求前阻断，未选来源不请求、不形成空快照或失败。
- 每个已选平台独立执行严格名称解析、身份确认、完整分页、逐专辑详情和完整性校验；网易允许汉字/拉丁双脚本完整名称段匹配，所有来源禁止任意子串或相似度匹配。
- 等待已选平台身份解析全部抵达；解析成功子集非空时集中在一个确认界面核对各来源已选结果的 Provider 原名和 ID，确认后只抓取成功身份子集；解析失败来源保留 `failed`，成功子集为空时不弹确认。
- 已选平台可以并行抓取；取消和重试均作用于该批次固定的抓取来源子集。
- 预览只展示本批次已抓取平台各自的来源摘要、计数、状态和来源级完整性说明，不展示或提供逐专辑明细及专辑选择。
- 每个来源自动获取全部合法专辑的完整详情；完整性校验后只组装该来源已确认歌手参与的歌曲。主动排除不产生逐专辑异常，真实逐专辑异常仍必须聚合到来源级完整性说明。
- 各来源快照按来源内专辑 ID 和稳定歌曲 ID 处理；来源内实际去重时提供结构化核查，不跨来源合并或去重专辑、歌曲或歌手身份。
- 抓取完成后的页面状态与抓取/生成两组来源选择在当前应用会话内跨路由保留；普通导航不视为重试，也不自动请求 Provider。
- 抓取后默认勾选全部合格来源作为生成目标，允许改为任意非空子集；非空 `partial` 可选，`failed`、`cancelled` 或全部合法专辑经歌手参与筛选后为 0 首的来源不可选。
- 只对选中生成来源检查同名本地歌单；用户确认后仍创建新的同名歌单，不覆盖、不合并既有歌单。
- 选中生成子集采用全有或全无的尽力补偿写入，回滚失败必须报告残留；未选来源不创建、不回滚。
- 新歌单继续使用洛雪普通本地歌单持久化和原生批量下载链路。

### 不包含

- 跨来源歌手 ID、专辑 ID 或歌曲 ID 的映射。
- 跨来源专辑合并、语义去重、版本择优或自动补源。
- 只成功创建选中生成子集中的部分歌单并把该结果提示为整批成功。
- 自动覆盖、清空或合并现有同名本地歌单。
- 抓取完成或歌单创建完成后自动开始下载。
- 新增在线歌单同步语义、数据库迁移或第二套下载器。
- 为绕过 Provider 缺陷而使用歌曲搜索结果宣称专辑完整。

## 业务规则

以下规则由 [BIZ-20260809-03](../decisions/BIZ-20260809-03-four-source-discography-playlist-strategy.md) 确认，并由 [BIZ-20260809-04](../decisions/BIZ-20260809-04-album-summary-and-dedup-audit.md)、[BIZ-20260809-05](../decisions/BIZ-20260809-05-partial-direct-apply-and-dedup-summary.md)、[BIZ-20260810-01](../decisions/BIZ-20260810-01-playlist-name-with-track-count.md)、[BIZ-20260810-02](../decisions/BIZ-20260810-02-source-subset-and-artist-alias-confirmation.md) 和 [BIZ-20260817-01](../decisions/BIZ-20260817-01-filter-album-tracks-by-confirmed-artist.md) 局部修订：

1. 用户一次只输入一个歌手名称，并在抓取前从默认全选的四个平台中选择一至四个来源；零来源不得请求。
2. 所选平台至少要求规范化完整展示名相等；网易额外接受完整连续汉字段与完整拉丁字母段组成的双脚本展示名中，一个完整脚本段与输入相等。各 adapter 按 Provider 原始稳定顺序选择首个合法结果；网易不得全局优先 `exact`，所有来源禁止任意子串、前后缀、编辑距离、拼音、相似度或跨平台 ID 匹配。
3. 等待所选来源身份解析全部抵达；解析失败来源保留 `failed`，只对成功身份非空子集弹出一次统一确认并展示 Provider 原名和 ID；成功身份为零时不弹确认并阻断批次。
4. 已抓取目录快照独立形成、独立校验；每个来源自动使用全部合法专辑，不提供逐专辑明细或选择，不跨来源合并或去重。
5. 所选来源抓取可以并行；取消和重试必须覆盖本批次抓取子集，重试不得把新响应拼接到旧快照。
6. 抓取后默认选择全部合格来源生成歌单；`partial` 只要有合法歌曲即可选择，`failed`、`cancelled` 和无歌曲来源不可选，但不阻断其他合格来源组成非空生成子集。
7. 歌单名称使用去除首尾空白后的输入歌手名，严格采用无空格格式“`<输入歌手名>-<酷狗|qq|网易|酷我>-<N>首`”；`N` 为该来源最终去重后实际提交歌曲数。
8. 同名检查只覆盖选中生成来源，并只触发风险提示；确认后始终新建，不覆盖或合并已有歌单。
9. 选中生成子集按全有或全无目标执行；任一失败都回滚本次已新建的选中歌单，回滚残留必须显式报告。
10. 生成结果是普通本地歌单，不绑定在线歌单同步，也不自动下载。
11. 抓取完成后，当前应用会话内的路由切换不得丢弃或刷新本批次页面状态及两组来源选择；页面不再保存 partial consent，显式重新获取才替换批次并重置生成选择，刷新或重启不恢复抓取快照。
12. 每个来源先以完整专辑详情校验 Provider 完整性，再按联合艺术家独立名称项匹配该来源已确认的 `ArtistRef.name`；匹配歌曲进入稳定 ID 去重和写入，不匹配歌曲排除。筛选不重新压缩可靠曲序，也不把正常减少误报为 `partial`。
13. 来源内实际移除重复项时必须提供精简的结构化人工核查：保留平台、类型、歌曲/歌手、单一稳定 ID 或 Provider ID，以及保留/移除专辑名、albumId、曲序；最终歌单歌曲去重与 Provider/专辑内早期去重仍可区分，无去重时不显示，不展示快照位置或重复 Provider ID，不得伪造不可得字段。

## 功能需求

### FR-01 四来源歌手解析与统一确认

- 输入不能为空；去除首尾空白后作为本批次稳定的 `inputArtistName`。
- 页面提供 `kg`、`tx`、`wy`、`kw` 抓取来源复选项，空页面默认全部选中；调用计划时必须固定一至四个去重后的来源，零来源在 Provider 请求前阻断。
- 每个已选来源接受规范化输入与 Provider 完整展示名相等的 `exact`。网易还接受 `alias_exact`：输入和 Provider 展示名中恰有一方是“完整连续汉字段 + 完整拉丁字母段”或相反顺序的双脚本组合名，另一方与其中一个完整脚本段相等；拉丁段至少两个字母，可含单词间空白。
- 禁止任意 `contains`、不完整前后缀、编辑距离、拼音或专辑数推断；“刘雨昕”可匹配完整别名段“刘雨昕XIN LIU”，“刘雨”不得匹配。
- 身份结果必须返回来源、Provider 完整歌手名称、来源内 ID、可用头像及声明专辑数；可选字段缺失不得伪造。搜索结果按来源内 ID 去重时不得改变首个出现项的稳定顺序。
- 系统必须等待全部所选平台身份解析 settled；没有合法候选、请求失败或返回非法身份的平台保留可定位的 `failed`，不进入确认，也不阻断其他成功身份。
- 成功身份子集非空时只弹一次确认界面，展示每项 Provider 原名、ID、头像及可用声明专辑数。用户取消或关闭时整批结束，且不得开始后续专辑请求。
- 成功身份子集为零时不弹确认，批次直接 `blocked`；未选平台不得请求，也不得记为失败。

### FR-02 四来源目录抓取

- 每个已选平台都必须穷尽歌手专辑分页，并对每张专辑穷尽详情分页。
- 每个已选平台最终曲目只以本来源专辑详情为准；歌手歌曲列表只可作为调度或异常提示。
- 已选平台可以并行计划；每个平台内部必须保留有限并发、有限重试、分页循环保护和 Provider 限流边界。
- 批次取消后本批次全部所选来源都停止创建新请求；批次重试按当时的抓取来源选择重新解析身份并重建快照。
- 网易主 `/api/album/{albumId}` 以 HTTP 200 返回精确 `code=-462`、`data.verifyType=50` 验证拦截 envelope 时，adapter 必须切换 `/api/v1/album/{albumId}` 取得同一专辑备用详情；主端点合法成功时不得额外请求备用端点。
- 网易 v1 备用详情必须按现代 `album` + 根级 `songs` 结构严格校验 canonical albumId 和必需歌曲字段，不能拼接两路曲目或放宽 `MusicInfoOnline` 合同；备用成功不得仅因主端点曾被拦截而降级来源。
- 网易主端点返回其他非 200 Provider code，或 fallback 返回任意非 200 Provider code 时归类为单一、可重试的 `provider_unavailable`；Provider code 为 200 但结构非法时仍归类为 `invalid_provider_response`。
- 网易歌曲的稳定 ID、名称、歌手、专辑归属和时长均合法，但 Provider 返回 `no=0` 或没有独立曲序字段时，不得丢弃歌曲；adapter 按当前专辑详情响应顺序补一基曲序。正整数曲序原样保留，负数、非整数或非数字曲序仍为非法响应。
- 酷我专辑详情提供可信 `*.kuwo.cn` 的 `/star/albumcover/240/` 缩略图时，目录 mapper 必须在写入歌曲 `meta.picUrl` 前将路径尺寸段规范化为 `500`；非酷我域名、相对 URL、查询参数数字、其他尺寸或非法 URL不得宽泛改写。

### FR-03 独立快照与统一预览

- 每个平台分别返回 `complete`、`partial`、`failed` 或 `cancelled`，并展示预期/实际专辑数、歌曲数及可定位异常。
- 页面必须同时展示本批次已选平台的进度和结果，不用一个平台的成功掩盖另一个平台的失败；未选平台不展示伪造的空结果。
- 每个来源卡只展示来源摘要，不展示逐专辑名称、ID、状态、问题或选择控件；写入自动使用该来源全部合法专辑。
- 逐专辑异常必须聚合为来源级完整性说明，并据此判定 `complete`、`partial` 或 `failed`。
- 来源摘要只在根因和派生 issue 能定位到同一个 owner album、`issue.albumId` 等于 owner albumId 且 owner `actualCount=0` 时折叠 `album_incomplete`、`empty_catalog` 派生提示；底层完整 issues、状态判定和 apply 阻断语义保持不变。
- 最终歌单在来源内按稳定 `track.id` 去重并保留首次出现项；实际去重时，核查卡只要求展示平台、最终歌曲去重类型、歌曲名称、歌手、一个稳定 `track.id` 或 Provider ID，以及保留与移除专辑名称、albumId 和曲序。复制内容如保留必须与可见精简字段一致，不包含隐藏位置。
- Provider 分页或专辑详情内已提前移除的重复专辑/歌曲必须标明早期歌曲或早期专辑去重类型；卡片以 issue 标识符和保留快照生成 identifier-only 回退，明确标记 `exact: false` 和原始副本不可恢复。不可得的歌曲、歌手、标识符、专辑或曲序可以缺失，但不得反推或伪造被移除项。
- 去重核查不展示专辑位置、歌曲位置或全局稳定遍历位置，不同时重复展示等价去重键和 Provider song ID，也不在保留/移除两侧重复同一个 Provider ID；首次出现规则仍用于实际去重，但不再单列保留原因字段。
- 任一层级没有实际去重时，不显示对应核查卡；任何跨来源歌曲都不得相互折叠。
- 抓取完成后切换到其他路由再返回，必须保留输入名称、同一 `batchId`、`requestedSources`、已抓取来源摘要、`playlistSources`、来源级完整性说明、精简去重核查和 apply 结果；不存在逐来源 `partial` 授权状态。
- 返回页面不得自动请求 Provider；只有用户显式重新获取时才创建新批次并替换上述状态。
- 抓取页面状态只在当前应用会话内保留，不写入持久化存储；刷新或重启后从空状态开始。

### FR-04 批量写入条件

- `playlistSources` 必须是当前 `batchId` 已抓取来源中去重后的非空子集；零个来源时批量创建按钮禁用，不执行同名检查或写入。
- `complete` 或 `partial` 只要最终形成非空合法歌曲集合即可成为生成选项，不再要求逐来源接受不完整结果；抓取结束后默认选中全部此类来源。
- `failed`、`cancelled` 或没有合法歌曲的来源不可选，并说明来源和原因；只要仍有其他合格来源被选中，它们不阻断生成子集。
- 写入前再次展示全部选中目标名称、各来源合法专辑数和最终歌曲数；名称中的数量必须与对应最终歌曲数相同。
- core 必须复核每个生成来源属于当前 `requestedSources`、状态和歌曲集合仍合格；未选来源不得参与写入或改变结果。

### FR-05 来源歌单子集创建与补偿

- 对每个选中生成来源，目标名称固定为：
  - `<inputArtistName>-酷狗-<Nkg>首`
  - `<inputArtistName>-qq-<Ntx>首`
  - `<inputArtistName>-网易-<Nwy>首`
  - `<inputArtistName>-酷我-<Nkw>首`
- 每个 `N` 必须从该来源全部合法专辑中经歌手参与筛选、再按稳定 `track.id` 去重后的实际提交歌曲数组长度取得；Provider 声明数、筛选或去重前曲数和页面旧缓存不得作为名称数量。
- 目标名称预览、同名检查、core 实际创建和补偿失败残留报告必须使用同一目标名称。
- 存在任一选中目标同名歌单时，统一提示冲突名称；用户确认后仍为全部选中来源生成新的唯一歌单 ID。
- 不向现有同名歌单写入歌曲，不设置 `sourceListId`。
- 每个新歌单写入对应来源全部合法专辑中经歌手参与筛选、再按稳定 `track.id` 去重后的歌曲，不接受逐专辑子集；未选来源不创建歌单。
- 任一新建或加歌失败时，必须删除本次已创建的全部选中来源新歌单；不得删除未选来源歌单或批次开始前已存在的任何歌单。
- 补偿全部成功时结果为失败且无新增歌单；补偿部分失败时结果仍为失败，并返回全部残留歌单名称和 ID 供人工处理。

### FR-06 原生下载和持久化

- 批量创建成功后，本次选中生成的全部歌单均可在应用重启后继续存在。
- 页面可导航到创建结果，但不得自动创建下载任务。
- 用户从各来源歌单进入洛雪现有批量下载弹窗；音质、用户源、逐曲降级和错误处理继续沿用现有链路。

## 非功能需求

- Provider 是不受本项目控制的外部依赖；四个 adapter 都必须处理超时、失败、空数据、非法响应、限流、有限重试和取消。
- 每个来源必须有脱敏固定响应和离线合同测试；默认测试不得依赖实时平台。
- 四个平台的远端文本只能按普通文本渲染，不使用 `v-html`。
- 不新增生产运行时依赖，不进行数据库迁移。
- 批量写入必须具备幂等的批次内补偿边界，不得删除批次外用户数据。
- 现有酷狗单来源能力、在线歌单导入、搜索、播放、本地歌单和普通下载不得回归。

## 风险与约束

- 四个平台的字段、分页、限流和反爬策略不同，不能复用酷狗响应假设。
- 同一歌手名称在同一或不同平台都可能解析到多个主体；严格匹配和 Provider 稳定顺序仍只能形成待确认身份，必须依靠统一确认展示原名和 ID，不能把名称当作跨平台身份。
- 多个平台并行会放大网络请求量，adapter 必须各自限制详情并发并正确响应所选来源批次取消；未选 Provider 必须保持零调用。
- 本地歌单创建与加歌不是数据库事务，全有或全无只能通过尽力补偿实现。
- QQ、网易和酷我目录 adapter 的既有目录合同已通过离线测试；`BUG-20260810-01` 的严格别名顺序匹配已验证，但 Provider 接口、字段、签名和反爬策略仍可能变化。

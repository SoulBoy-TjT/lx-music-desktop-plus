本需求是独立的下载文件组织需求。`REQ-20260805-01` 只负责生成普通本地歌单并衔接原生下载，其范围明确排除了文件夹整理和下载目录重构；本需求不得反向改变其目录完整性规则或下载触发方式。

## 背景

当前下载设置仅支持“歌名 - 歌手”“歌手 - 歌名”“歌名”三种文件名格式；保存路径只能使用下载根目录，或在启用现有设置后按歌单名增加一级目录。用户下载完整专辑时，文件名缺少专辑曲序，目录也不能按艺术家和专辑归档。

当前通用歌曲信息和下载任务还没有完整表达专辑发行日期、专辑艺术家、碟号和曲序。后续实现不能用下载队列顺序伪造专辑曲序，也不能用占位日期伪造真实发布日期。

## 目标

1. 在下载设置的文件命名方式中增加“曲序. 艺术家 - 歌曲名”。
2. 用户启用专辑目录组织后，歌曲按“艺术家/发布日期 + 专辑名”保存。
3. 使用可靠的专辑元数据生成曲序和目录；元数据不足时按已确认规则保守回退。
4. 继续复用洛雪原生下载任务、进度、重试、持久化和关联文件保存能力。

期望完整示例：

```text
下载根目录：C:\Users
文件路径：C:\Users\蔡徐坤\2017-12-15 I Wanna Get Love\01. 蔡徐坤 - I Wanna Get Love.flac
```

扩展名由实际下载格式决定，不属于文件命名模板的一部分。

## 术语

- **曲序**：歌曲在对应专辑中的稳定顺序，不是搜索结果、歌单或下载队列中的位置。
- **文件艺术家**：曲目级艺术家，用于文件名中的“艺术家”；合作歌曲可以与专辑艺术家不同。
- **抓取目标歌手**：用户在歌手专辑目录中确认的歌手，也是生成歌单的归属歌手；用于 Easy Music 规则的一级目录。
- **专辑艺术家**：专辑级艺术家；没有抓取目标歌手上下文时作为一级目录的第一回退。
- **发行日期**：Provider 明确给出的有效日期；完整日期统一显示为 `YYYY-MM-DD`。
- **下载根目录**：用户在现有下载设置中选择的保存路径。

## 用户场景

### 场景一：按曲序命名完整专辑

用户在下载设置中选择“曲序. 艺术家 - 歌曲名”，下载蔡徐坤专辑时得到 `01. 蔡徐坤 - I Wanna Get Love.flac`，文件管理器按名称即可保持专辑顺序。

### 场景二：按歌手和专辑归档

用户将下载根目录设置为 `C:\Users`，启用歌手/专辑目录组织后，从“蔡徐坤 - 全专辑”歌单下载的歌曲保存到 `C:\Users\蔡徐坤\2017-12-15 I Wanna Get Love\`。即使其中某首合作曲的专辑艺术家不同，也继续归入已确认的抓取目标歌手“蔡徐坤”。

### 场景三：元数据不完整

普通搜索或旧歌单中的歌曲缺少可靠曲序、发布日期或专辑艺术家时，系统不使用下载队列位置或虚构日期。下载按已确认的回退格式继续，并向用户说明发生了回退。

## 范围

### 包含

- 在下载设置中增加新的文件名格式选项。
- 增加按歌手和专辑组织目录的用户可配置方式。
- 为新建下载任务解析、校验并固化文件名和目标目录所需元数据。
- 适用于单曲下载、普通歌单批量下载及歌手全专辑歌单进入的原生下载流程。
- 处理现有“按歌单名分组”设置与新目录方式的兼容关系。
- 保证歌词等随歌曲保存的关联文件与音频位于同一目录，并使用一致基名。
- 处理 Windows 非法字符、尾随点或空格、保留名称、路径穿越、路径长度和同名冲突。
- 补充设置、命名、路径解析、元数据回退和下载任务写入测试。

### 不包含

- 自动开始下载或绕过现有音质确认和下载来源检查。
- 改变音频 URL 获取、自定义源、重试或下载传输逻辑。
- 移动、重命名或重新整理已经下载完成的文件。
- 使用歌曲名称模糊查询专辑元数据，或跨平台猜测、合并专辑。
- 为实现目录命名而扩大 `REQ-20260805-01` 的网易云、QQ 音乐支持范围。
- 修改 `easy-music` 项目。

## 功能需求

### FR-01 新增文件命名方式

- 下载设置的“文件命名方式”必须新增“曲序. 艺术家 - 歌曲名”选项。
- 元数据完整时，输出格式必须为 `<曲序>. <艺术家> - <歌曲名>.<扩展名>`。
- 曲序至少补齐两位；例如第 1 首为 `01`，不得输出下载队列位置。
- 文件名中的“艺术家”使用曲目级艺术家；目录第一级优先使用抓取目标歌手，使合作曲目不会因专辑艺术家变化被拆到其他歌手目录。
- 原有三种格式必须继续可用；是否改变默认值由关联 BIZ 明确，未经确认不得静默改变现有用户行为。
- 文件名必须在下载任务创建时确定并持久化，任务重启或重试不得因歌单顺序变化而改名。
- 当前设置值还被播放器标题和“复制歌曲名”等非下载场景复用；后续实现必须隔离下载专用曲序格式，或为非下载场景提供不会暴露未替换曲序的明确兼容行为。

### FR-02 新增专辑目录组织方式

- 用户启用专辑目录组织后，完整元数据的目标目录必须为：

  ```text
  <下载根目录>\<歌单归属歌手>\<YYYY-MM-DD 专辑名>\
  ```

- 日期与专辑名之间使用一个半角空格。
- 每个动态目录段必须独立清洗，最终路径必须仍位于用户选择的下载根目录内。
- 新目录方式与现有“按歌单名分组”的组合或互斥关系必须按关联 BIZ 实现，不得根据开关判断顺序产生隐式嵌套。
- 歌手全专辑入口的一级目录使用已确认并持久化的抓取目标歌手，不得解析可能被用户重命名的歌单名称。
- 普通入口没有抓取目标歌手时按“专辑艺术家 → 曲目艺术家”回退。
- 下载阶段不添加 `(N首)` 后缀，不在任务完成后移动已下载目录。

### FR-03 元数据来源与保守回退

- 曲序优先使用 Provider 明确返回的专辑曲序；无独立字段但已取得完整专辑详情时，可使用详情中的稳定顺序。
- 专辑目录必须优先使用明确的抓取目标歌手；缺少该上下文时再使用专辑艺术家、发行日期和专辑名，不得从文件名或歌单名反向猜测。
- 发布日期必须经过严格校验；缺失、非法或精度不足时不得伪造 `0000-00-00` 等日期。
- 缺少曲序、专辑名或艺术家时的文件名和目录回退规则，必须先由关联 BIZ 接受再实现。
- 发生回退时下载可以继续，但必须提供可理解、不过度重复的提示或结果说明。

### FR-04 多碟与曲序稳定性

- 多碟专辑的编号显示策略必须在关联 BIZ 中固定，且在同一专辑内具有稳定、可排序、无冲突的结果。
- 同一专辑同一曲目从不同入口创建下载任务时，应得到相同曲序和目录。
- 不得以当前勾选顺序、歌单排序或并发任务完成顺序决定曲序。

### FR-05 路径安全与冲突

- 艺术家、专辑名和歌曲名中的 Windows 非法字符必须按项目统一规则处理。
- 必须防止 `..`、绝对路径片段或分隔符使结果逃逸下载根目录。
- 必须处理 Windows 保留名称、尾随点/空格和超长路径；截断后仍要尽量保留可辨识信息和扩展名。
- 文件名同时包含歌手和歌曲名时，超出预算必须按语义字段分别缩短，在字符边界使用 `...` 标识省略，并保留曲序、字段分隔符、双方可辨识片段和真实扩展名；不得让长歌手列表把歌曲名完全挤掉。
- 截断结果必须稳定可复现并保留消歧能力；不同长名称不得因前缀相同而静默收敛到同一路径。
- 文件名预算必须覆盖最终音频和下载发布、格式校验、FLAC 规范化及所有权文件等内部文件组件的最长已知后缀；不得只保证最终可见名称合规而让内部文件超过 Windows 单段上限。
- 同名文件与重复下载任务继续复用或明确扩展现有冲突策略，不得静默覆盖已有文件。

### FR-06 设置与任务兼容

- 新设置必须通过项目统一设置机制保存，应用重启后仍生效。
- 升级后的现有用户必须保留升级前下载行为，除非主动选择新格式或新目录方式。
- 设置变更只影响此后新建的下载任务；已排队、下载中、失败待重试和已完成任务继续使用任务中固化的文件名和路径。
- 本需求不得自动移动或迁移既有下载文件。

### FR-07 原生下载衔接

- 单曲与批量下载都必须继续进入现有下载任务创建和执行链路。
- 音质选择、来源支持检查、任务持久化、暂停、重试和进度展示不得另建实现。
- 歌词等使用音频基名生成的关联文件必须跟随新的目录和文件基名。
- 播放器标题、列表展示和复制歌曲名等非下载行为不得因新增曲序格式出现原始模板、伪造序号或回归。

## 非功能需求

- 文件名与路径计算应集中在可测试的纯逻辑模块，Renderer 设置页不直接拼接最终磁盘路径。
- 不新增生产运行时依赖，不进行无关 Provider、播放或歌单重构。
- 路径结果在 Windows 上必须确定且可复现；测试不得依赖实时 Provider。
- 对缺失或非法 Provider 元数据应返回结构化原因，不能依赖解析异常作为正常分支。
- 后续 DEV 必须说明设置迁移、下载任务兼容、元数据模型扩展和回滚方式。

## 风险与约束

- 普通搜索结果、旧歌单或部分 Provider 可能没有可靠曲序和完整发布日期。
- 本次修订前已经生成的歌手全专辑歌单没有 `discographyArtist`；系统不会从旧歌单名猜测归属歌手，需要重新生成歌单才能使用新的一级目录语义。
- 多艺术家、多碟、豪华版和同名发行物的目录名称可能冲突。
- Windows 单段名称与完整路径长度限制会影响长艺术家、专辑和歌曲名。
- 下载发布与校验会从最终名称派生更长的内部文件名；新增或调整内部后缀时必须同步复核下载目标预算，否则最终名称可创建仍不代表发布链可创建。
- 下载任务会持久化，若只读取实时设置而不固化最终路径，重启和重试可能写入不同位置。
- 当前按歌单名分组是布尔设置；若新增并列布尔开关，两个开关同时启用时会产生歧义。

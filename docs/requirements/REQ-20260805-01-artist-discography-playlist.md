## 背景

洛雪现有功能可以导入在线平台歌单、创建本地歌单和批量下载，但没有把“平台歌手”转换成“歌手专辑目录”的用户流程。歌曲搜索按相关性返回结果，不能证明已经覆盖一个歌手的全部专辑。

仓库中酷狗、网易云和 QQ 音乐已有未统一导出的歌手信息、专辑列表和歌曲列表实现。本需求在不引入新的在线目录服务、不复制 easy-music 下载队列的前提下，组装这些现有能力，并复用洛雪本地歌单与下载流程。

## 目标

用户提供一个受支持来源及歌手名称后，系统能够：

1. 识别并确认唯一歌手。
2. 获取该来源返回的全部歌手专辑，并逐张取得完整专辑曲目。
3. 通过来源内的专辑 ID 组装并校验歌手专辑目录。
4. 展示目录快照及完整性报告，供用户确认。
5. 将确认后的歌曲写入一个普通洛雪本地歌单。
6. 从该歌单调用洛雪原生批量下载流程。

术语以仓库根目录 [CONTEXT.md](../../CONTEXT.md) 为准。

## 用户场景

### 场景一：生成歌手专辑歌单

用户选择酷狗音乐并输入“薛之谦”。系统精确搜索歌手名称，展示候选歌手名称、ID 和头像供确认，再拉取全部专辑并补齐每张专辑的完整曲目，按专辑分组显示数量和异常。用户确认后创建“薛之谦 - 全专辑”本地歌单。

### 场景二：处理不完整结果

某一分页请求失败时，系统明确标记目录快照为“部分完成”，显示失败阶段和可重试项，不得将其提示为“全专辑”。用户可以重试；只有明确确认后才允许把部分结果写入歌单。

### 场景三：进入原生下载

用户在生成的本地歌单中点击批量下载，继续使用洛雪现有音质选择、用户自定义源、任务持久化、重试和下载进度能力。目录获取成功不等于歌曲可下载。

## 范围

### 包含

- 新增“歌手专辑目录”入口、来源选择和歌手名称输入；数字 ID 与官方链接作为兼容输入保留。
- 第一阶段仅支持同时具备歌手专辑列表和专辑详情实现的 `kg`，完成一个可独立验收的纵向切片。
- 对歌手信息、专辑列表和专辑详情执行完整分页。
- 可以用歌手歌曲列表预填专辑分组或优化请求调度，但每张专辑仍必须调用专辑详情，最终曲目和完整性只以专辑详情去重结果与声明曲数为准。
- 使用同一来源的专辑 ID 判断歌曲归属，保留专辑详情中的全部曲目，包括合作、伴奏或未把目标歌手列为曲目艺人的内容。
- 按来源内稳定歌曲 ID 去重，不按歌名合并不同版本。
- 展示歌手、来源、专辑数、歌曲数、专辑分组、缺曲和分页异常。
- 创建独立的普通本地歌单，或经用户确认写入指定普通本地歌单。
- 复用 `createUserList`、`addListMusics` 和原生批量下载入口。
- 提供取消、重试、空数据、非法响应和 Provider 不可用的明确状态。
- UI、文案、主题、交互、国际化和列表行为沿用洛雪现有模式。

### 不包含

- 自动合并或静默选择不同名称的模糊歌手结果。
- 把 `wy`、`tx`、酷我、咪咕等尚无可靠专辑详情 adapter 的来源纳入第一阶段完成范围。
- 跨平台专辑合并、跨平台歌曲语义去重或自动补源。
- 承诺“全网绝对完整”；结果只代表选定来源在获取时刻返回的目录快照。
- 自动配置或内置音频 URL 来源。
- 未经用户选择音质便自动启动下载。
- 改变现有在线歌单导入、在线搜索、本地歌单同步和下载数据结构。
- 文件夹整理、下载目录重构或 FLAC 转 MP3。

> 本节记录酷狗第一阶段的范围边界。2026-08-09 起，QQ、网易、酷我的来源接入及一次四平台预览/建歌单由 [REQ-20260809-01](REQ-20260809-01-four-source-artist-discography-playlists.md) 独立定义和验收，不回写为本 REQ 已完成能力。

## 业务规则

以下规则为 [BIZ-20260805-01](../decisions/BIZ-20260805-01-discography-scope-and-source.md) 的推荐方案，只有该 BIZ 进入 `accepted` 后才成为实现依据：

1. 一次操作只使用一个在线来源和一个精确歌手引用。
2. “歌手专辑目录”以该来源返回的歌手专辑列表为准，不使用歌曲搜索结果推断全集。
3. 每张专辑以专辑详情返回的完整曲目为准；不能仅以目标歌手歌曲列表过滤后宣称专辑完整。
4. 平台返回的不同专辑 ID 视为不同发行版本，不按名称自动合并。
5. 目录快照不完整时默认禁止直接创建歌单；用户明确接受部分结果后可以继续。
6. 生成的歌单是普通本地歌单，不使用在线歌单的 `sourceListId` 同步语义。
7. 下载必须由用户进入原生音质选择流程；“已收录”“可下载”“下载完成”分别记录。

> 2026-08-09 用户确认的新四平台批次由 [BIZ-20260809-03](../decisions/BIZ-20260809-03-four-source-discography-playlist-strategy.md) 局部修订“一次一个来源”和默认歌单命名。上述规则继续作为酷狗首期及单来源目录快照的历史验收口径。

## 功能需求

### FR-01 歌手名称输入

- 用户必须选择来源。
- 输入默认接受歌手名称；名称必须在所选来源的歌手搜索结果中完全匹配，数字 ID 与官方歌手页面链接继续作为兼容输入。
- 多个完全同名结果按 Provider 顺序选择首项，但系统必须先展示歌手名称、ID 和头像供用户确认，再允许开始获取。
- 无法唯一识别时不得猜测或静默选择。

### FR-02 目录获取

- 系统必须取得歌手信息、全部专辑分页和每张专辑的完整详情分页。
- 歌手歌曲分页只可作为预填分组、异常提示或请求调度优化；无论其曲数是否与专辑声明一致，每张专辑都必须回源获取完整详情。
- 分页终止必须依据 Provider 返回的 `total/limit` 或明确的无下一页条件。
- 必须防止重复页、空页循环和超过合理上限的无限请求。
- 用户取消后不得继续发起新的分页请求。

### FR-03 目录组装

- 系统必须使用来源内专辑 ID 建立专辑集合，并保留专辑详情返回的全部曲目。
- 歌曲必须转换成合法的 `LX.Music.MusicInfoOnline`。
- 同一来源内相同稳定歌曲 ID 只保留一次。
- 专辑详情返回的歌曲缺少稳定歌曲 ID、专辑归属或必要音乐字段时必须进入异常报告，不得静默混入。

### FR-04 完整性报告

- 报告必须区分 `complete`、`partial`、`failed` 和 `cancelled`。
- 必须展示 Provider 报告数量、实际取得数量和每张专辑的预期/实际歌曲数。
- 分页失败、数量不一致、空专辑、未知歌曲和重复 ID 必须有可定位说明。
- “complete”只代表本次来源响应在既定规则下完整，不代表跨平台绝对完整。

### FR-05 歌单写入

- 写入前必须展示目录快照并获得用户确认。
- 创建失败时不得留下只有名称而没有歌曲的伪完成歌单；若现有写入无法原子完成，必须回滚空歌单或明确提示恢复方法。
- 写入既有歌单时沿用洛雪现有重复 ID 规则，不覆盖既有歌曲。
- 生成的歌单不得与平台在线歌单同步更新逻辑绑定。

### FR-06 原生下载衔接

- 歌单结果必须可进入洛雪现有批量下载弹窗。
- 音质选择、来源支持检查、下载任务创建和错误处理不得重复实现。
- 批量音质是整批歌曲的优先音质；只要每首歌曲都能解析到歌曲与当前用户源共同支持的音质，该档音质就可选择。
- 某首歌曲不支持优先音质时，必须按 [BIZ-20260807-01](../decisions/BIZ-20260807-01-batch-download-quality-fallback.md) 向下选择共同支持的最高音质，并在弹窗中明确提示存在逐曲自动降级。
- 当前用户源不支持歌曲来源，或任一歌曲不存在任何共同支持音质时，必须禁用对应操作并说明原因。

## 非功能需求

- Provider 是不受本项目控制的外部依赖；实现必须处理超时、失败、空数据、非法响应、重试、限流和取消。
- 目录组装逻辑必须能通过注入的假 adapter 离线验证，测试不得依赖实时在线平台。
- 远端歌手、专辑和歌曲文本必须按普通文本渲染，不使用 `v-html`。
- 不新增生产运行时依赖；测试工具如需新增，只能作为开发依赖并在 DEV 中说明理由。
- 不进行数据库迁移；生成结果继续使用现有本地歌单和下载持久化结构。
- 现有在线歌单导入、搜索、播放和下载路径不得回归。

## 验收标准

- [ ] AC-01：对 `kg` 的合法歌手名称，能够完全匹配并确认正确来源和歌手身份；不同名称的模糊结果、非法或不匹配输入不会开始获取，数字 ID/官方链接仍兼容。
- [x] AC-02：离线多页样例中，每一页专辑和专辑详情都被请求一次且只请求一次，不跳页、不重复、不无限循环。
- [x] AC-03：每张专辑取得完整详情曲目；合作、伴奏等非目标歌手独唱曲目不会因歌手过滤而丢失。
- [x] AC-04：相同来源、相同稳定歌曲 ID 去重；不同专辑 ID 或不同歌曲 ID 的发行版本不会因同名被合并。
- [x] AC-05：只有每张专辑的去重实际曲数与声明曲数一致时，完整样例才返回 `complete`；报告的专辑数、歌曲数和分组计数与样例一致。
- [x] AC-06：任一中间分页失败时返回 `partial` 或 `failed`，显示可重试阶段，且不会默认创建歌单。
- [x] AC-07：取消操作后停止新请求并返回 `cancelled`，不会创建歌单或下载任务。
- [x] AC-08：用户确认完整快照后，能创建一个普通本地歌单，歌曲均为合法 `MusicInfoOnline`，重启应用后仍存在。
- [x] AC-09：歌单创建或歌曲写入失败时不会显示成功；不存在未说明的空歌单残留。
- [ ] AC-10：从生成歌单全选歌曲可以打开原生批量下载弹窗；最高音质可作为优先音质，部分歌曲不支持时逐曲降级到共同支持的最高音质并显示提示；不存在共同音质时禁用。
- [x] AC-11：现有在线歌单导入、歌单同步、歌曲搜索和普通批量下载仍可使用。
- [x] AC-12：相关自动化验证、`npm run lint`、`npm run build:renderer` 与最终 `npm run build` 通过；实时 Provider 冒烟结果单独记录，不能替代离线验证。

## 验收证据要求

- 酷狗来源至少一组多页歌手专辑与多页专辑详情离线固定样例。
- 同名歌手、空目录、重复页、缺少 albumId、重复歌曲 ID、不同版本同名歌曲的回归样例。
- 生成歌单前后的歌曲数量和本地持久化证据。
- 原生下载弹窗调用及不支持来源/音质的界面证据。
- PROG 中逐项记录实际执行的命令、结果和未执行原因。

## 风险与约束

- 歌手模块当前没有统一导出，且存在本 REQ 审查期间发现的阻断缺陷。
- 在线平台接口属于外部 Provider，字段和分页行为可能变化。
- 平台对“专辑、EP、单曲、现场、精选、重制版”的分类不统一，必须先确认 BIZ 口径。
- 搜索成功、目录完整、加入歌单、当前可下载和下载成功是五种不同状态，不得合并成一个成功提示。

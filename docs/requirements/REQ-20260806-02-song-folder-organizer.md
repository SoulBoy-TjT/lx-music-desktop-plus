# 歌曲文件夹整理与音频可播放性检查

## 2026-09-11 调整：移除完整解码检查

本节替代下文有关音频检查入口、FFmpeg 依赖、可播放判定及必须先检查才能整理的旧规则。歌曲整理只执行目录与文件属性扫描，保留“重新加载”“整理”“查看详情”“打开文件夹”，不再提供“检查”或音频检查状态，不启动 FFmpeg。

整理从最新完整快速扫描开始：预览时重新读取当前歌手的目录事实，并保存一次性预览令牌和文件身份/大小/修改时间；确认后执行时复核歌曲集合与文件属性，变化则要求重新加载。清理确认、回收站、硬链接至少保留一份、播放/下载占用、重解析点边界、日志、回滚、重新计数与目录改名保持有效。硬链接保留路径只按层级、路径长度、自然排序决定，不依赖可播放状态。

整理不再识别损坏音频，不据此清理任何 MP3/FLAC。FFmpeg 继续供独立 FLAC 转 MP3 与下载格式校验使用。验收要求：无 FFmpeg 也能扫描和整理；无需先检查；歌曲在预览后变化时阻断；清理与改名安全回归通过。

## 背景

洛雪已经可以把新下载歌曲按歌手和专辑目录保存，但尚不能核对落盘 MP3/FLAC 是否能够完整解码，也不能按磁盘中的实际歌曲数量统一歌手和专辑文件夹名称。用户还需要定位和清理非 MP3/FLAC、重复硬链接、重解析点及空目录。

本需求参考 `easy-music` 已确认的目录层级、计数后缀、幂等重命名语义和文件夹整理工作区，但所有磁盘修改都必须限制在用户主动操作的单个歌手目录内。清理操作只允许移入 Windows 回收站，不照搬永久删除、关闭资源管理器或自动移动损坏音频等行为。

## 目标

1. 在 Windows x64 上提供独立的“歌曲整理”页面，其他平台和架构隐藏入口。
2. 从默认下载路径或用户指定目录发现歌手、专辑及 MP3/FLAC。
3. 首次和重新加载先快速展示不调用 FFmpeg 的目录统计；由用户点击“检查”后使用内置 FFmpeg 对 MP3/FLAC 执行全文件解码检查。
4. 通过五列歌手表格、状态标签和按需详情弹窗展示整理计划与异常，并支持在资源管理器中定位父目录或歌手目录。
5. 将原清理与重命名合并为单个歌手行“整理”：基于最近有效检查结果先安全清理已确认目标，再按唯一物理 MP3/FLAC 数量统一歌手和专辑后缀。
6. 整理达到可恢复终态后只执行一次不调用 FFmpeg 的轻量目录刷新，立即展示真实改名路径和数量；不自动完整解码。
7. 失败、跳过和回滚结果保留用于核查；无法证明检查结论继续有效时明确提示重新检查。
8. 与下载任务、本地歌曲路径和已整理数量后缀目录保持一致，避免整理后产生旧路径或重复目录。

## 术语

- **歌曲整理根目录**：包含一个或多个歌手目录的父目录；根目录中的直属文件完全忽略。
- **歌手目录**：歌曲整理根目录的直接子目录，即使没有歌曲也作为歌手项。
- **专辑目录**：歌手目录的直接子目录；其更深层目录只参与递归统计，不作为独立专辑。
- **可播放**：MP3/FLAC 能从头到尾完成解码。
- **无法播放**：解码器已经实际处理文件并确认格式或音频数据错误。
- **检查失败**：无权限、占用、超时、扫描期间变化或校验器异常导致本次无法完成判断，不能据此认定文件损坏。
- **不支持文件**：歌手目录内除 MP3/FLAC 外的所有普通文件。
- **重解析点**：符号链接或 Windows 目录联接；扫描不跟随其目标。
- **快速统计快照**：目录枚举完整结束并包含稳定任务 ID、路径、类型、物理身份、计数和静态异常的本次结果；不调用 FFmpeg，也不证明音频可播放。
- **深度验证快照**：基于同一快速统计版本完成全部计划音频校验后的结果；允许存在单文件“检查失败”，只有仍有效的快照可以发起整理。
- **稳定物理文件身份**：文件系统提供的卷与文件标识组合；必须从读取起使用无损表示，不能将超过 JavaScript 安全整数范围的 64 位标识先转换为 `number`。

## 目录模型示例

```text
D:\Music
├─ 根目录文件.mp3                 # 完全忽略
├─ 蔡徐坤                         # 歌手目录
│  ├─ 2017-12-15 I Wanna Get Love # 专辑目录
│  │  ├─ CD1                      # 专辑内部目录，不单独重命名
│  │  │  └─ 01. Song.flac
│  │  └─ cover.jpg
│  └─ 单独歌曲.mp3                # 只计入歌手，不属于专辑
└─ 空歌手                         # 保留并可重命名为“空歌手（0首）”
```

## 范围

### 包含

- 仅支持 Windows x64；本需求只构建和验证 Windows x64 安装包。
- 原“工具”改名为“专辑抓取”，新增独立“歌曲整理”入口；非 Windows x64 隐藏歌曲整理入口。
- 根目录默认跟随当前下载路径，并通过“选择指定目录”或“使用下载目录”切换；指定目录持久化。应用启动后在 Main 侧后台预扫描当前有效目录，不阻塞主窗口显示。
- 新安装用户默认把下载目录模式设为“按歌手和专辑”；已有用户升级时保留原目录模式，且不额外显示目录结构提示。
- 递归发现歌手目录内的文件和目录，但不处理根目录直属文件。
- 快速统计不调用 FFmpeg；用户点击“检查”后对 MP3/FLAC 执行完整解码，并区分可播放、无法播放、检查失败。
- 使用克制的全宽目录整理工作区：紧凑“扫描目录”轨道，以及“歌手文件夹、歌曲数、目标名称、状态提示、操作”五列表格；扫描状态不固定展示，详情按需弹出。
- 行操作改为“检查”和“整理”：检查建立深度验证快照，整理合并原清理与重命名。
- 所有清理目标先展示数量、大小、保留路径和待清理路径，经二次确认后移入回收站。
- 整理先执行经二次确认的安全清理，再执行歌手及其全部专辑的数量后缀重命名。
- 整理结束后只执行一次不解码的轻量目录刷新，并保留成功、跳过、失败和回滚结果。
- 自动化测试、Windows x64 打包验证、人工验收、文档和进度同步。
- 页面路由切换期间保留结果和任务监听；应用重启后清空。
- 下载占用隔离、已完成任务路径同步、本地歌曲身份同步、显式检查完整校验和异常中断恢复。

### 不包含

- Windows x86/arm64、Win7、Linux 或 macOS 的歌曲整理入口、FFmpeg 资源和验收。
- 根目录直属文件的扫描、统计、定位、清理或重命名。
- MP3/FLAC 以外格式的解码支持。
- 自动删除、移动、修复或转码无法播放、检查失败的 MP3/FLAC。
- 普通重复音频的内容哈希判重；只处理文件系统可证明的重复硬链接。
- 永久删除；回收站不可用时不得降级为永久删除。
- 修改音频标签、歌曲文件名、曲序或发布日期。
- 自动监控目录内容变化或跨应用重启保存扫描快照；每次应用启动仍重新建立一次不使用跨扫描缓存的后台快照。
- 把快速统计结果冒充完整音频检查，或在没有有效深度验证快照时执行整理。
- 修改 `easy-music` 项目。

## 功能需求

### FR-01 根目录选择与发现

- 默认根目录动态跟随当前下载路径；用户也可通过“选择指定目录”使用持久化的自定义目录，并通过“使用下载目录”恢复默认模式。
- 应用完成设置、数据库和 IPC 初始化后，在 Main 侧对当前有效目录发起一次后台快速统计；该任务不得延迟主窗口显示。页面打开时接管相同根目录的进行中任务或已完成快照，不重复扫描；配置根变化也只由 Main 发起，Renderer 清空旧结果并等待新的运行态。
- 成功选择新目录、切回下载目录，或使用下载目录期间在设置页改变下载路径时，视为根目录变化：立即清空旧结果并自动扫描新目录。
- 取消目录选择时保留原目录和原结果，不触发扫描。
- 页面统一使用“扫描目录”称谓，标题区不再提供“扫描”或“打开目录”；歌手行“打开文件夹”定位并选中歌手文件夹，不直接进入该文件夹。
- 根目录的每个直接子目录均作为歌手项；根目录直属文件完全忽略。
- 一级目录中严格匹配 FLAC Converter 输出名称 `<base> MP3`、`<base> MP3（N首）`、`<base> MP3(N首)` 的目录不作为歌手项；匹配按 Windows 大小写不敏感和成对括号规则执行，不使用任意 `contains`。快速统计和检查必须一致排除。
- 歌手目录的直接子目录作为专辑项；专辑内部更深目录只递归统计，不单独重命名。
- 根目录不存在、无权限或不是目录时终止扫描，由 Main 记录失败原因并禁止磁盘修改。
- 不跟随符号链接、目录联接或其他重解析点。

### FR-02 音频完整解码

- 扩展名按大小写不敏感规则识别 `.mp3` 与 `.flac`，扩展名匹配本身不能判定可播放。
- 每个 MP3/FLAC 必须从头到尾解码；文件头、元数据或能开始播放均不足以标记为可播放。
- 零字节、格式伪装和解码数据错误归为“无法播放”。
- 无权限、占用、超时、文件变化和单文件进程异常归为“检查失败”。
- FFmpeg 整体缺失、无法启动或目录枚举不完整时，扫描任务失败或部分失败，禁止磁盘修改。
- 校验只由用户点击“检查”触发并使用受控并发；检查运行期间不提供暂停或取消入口，也不由应用退出流程取消。Service 仅可为异常收敛、任务替换和自动化测试保留内部中止机制，已完成结果按快照版本判断是否仍有效。
- 启动、目录切换、重新加载和整理后刷新只建立不调用 FFmpeg 的快速统计；每次显式检查重新完整解码当次发现的 MP3/FLAC，同一次检查内可按稳定物理文件身份复用一次解码结果。

### FR-03 异常结果与定位

- 页面使用全宽目录整理工作区：“扫描目录”轨道单独成行，五列表格作为剩余空间的唯一主区域；表头吸顶，结果区内部滚动，不固定展示扫描状态或最近详情。
- 路径、详情弹窗、表格悬浮和状态标签使用 LX 现有语义背景、边框及文字变量，不使用大面积高不透明度主色背景。
- 页面不提供独立汇总卡、异常列表或异常筛选；正常歌曲也不逐文件展示。
- 异常类型包括：无法播放、检查失败、非 MP3/FLAC、重复硬链接、重解析点、空目录及操作失败。
- 歌手行可同时显示“待清理”“待重命名”“音频异常”“清理受阻”“重命名受阻”“操作受阻”等状态标签和必要原因；泛化“操作受阻”只用于两类操作均被阻塞的情况。
- 点击“查看详情”后，详情弹窗只展示该歌手的阻塞原因及异常名称、相对路径、类型、大小、状态和原因，不重复歌手汇总、歌手目标名称或逐专辑正常信息；没有异常或阻塞时只显示一句简洁提示。长内容内部滚动且允许选择复制。
- 整理的清理预览与二次确认使用同一个详情弹窗；整理和恢复操作结束后使用同一弹窗反馈成功、跳过、失败及回滚结果，轻量刷新不得改写已经打开的内容；页面失活期间完成的操作在返回后再展示结果，不覆盖其他页面。
- 同一应用会话中，轻量刷新后再次点击该歌手“查看详情”仍须追加最近一次整理的失败、回滚失败及异常跳过记录；成功步骤不进入普通详情。同一歌手下一次操作、根目录变化或应用重启按规则清理旧记录。

### FR-04 计数与硬链接

- `N首` 按目录内唯一物理 MP3/FLAC 数量计算，包括可播放、无法播放和检查失败。
- Windows 64 位卷与文件标识必须无损读取并形成稳定身份；精确身份不同的普通文件分别计数，即使它们转换为 JavaScript `number` 后相等。
- 重复硬链接不增加歌曲数量；普通内容相同但文件身份不同的音频分别计数，不做内容判重。
- 只有位于同一专辑范围内的重复硬链接才允许进入自动清理；专辑内部更深目录仍属于该专辑范围。
- 跨歌手、歌手根目录与专辑之间、不同专辑之间的硬链接组始终跳过并在详情中显示全部路径，不受当前行操作影响。
- 同一专辑内的硬链接保留路径优先级为：可完整解码且扩展名匹配实际格式的 MP3/FLAC、层级更浅、相对路径更短、中文数字自然排序更前。
- 同一个硬链接组清理时必须至少保留一个路径，绝不得删除最后一个链接。
- 专辑计数在各专辑范围内独立去重，歌手计数在整个歌手范围内去重；存在跨专辑硬链接时允许专辑曲数之和大于歌手总数，并显示原因。

### FR-05 检查与整理清理阶段

- “检查”由单个歌手行发起并建立深度验证快照；“整理”只作用于该歌手，并只使用同一根目录和歌手仍有效的最近一次深度验证快照。
- 预览按类别展示重复硬链接的保留/清理路径、非 MP3/FLAC、重解析点和预计清理后为空的目录。
- 执行前显示数量、总大小和完整清单，并使用二次确认。
- 执行时重新确认路径仍在根目录和当前歌手内、类型未变化且仍符合计划；新增或变化的目标跳过并报告。
- 重解析点只移除链接入口，不跟随、移动或删除目标；无法证明安全时跳过。
- 所有文件、链接入口和目录只移入 Windows 回收站；回收站不可用时跳过并报告。
- 文件及链接处理后，从最深层开始删除真正为空的目录；歌曲整理根目录和歌手目录永不删除。
- 无法播放或检查失败的 MP3/FLAC 不进入清理计划。
- 全部非 MP3/FLAC 继续进入清理计划，包括 `.lrc`、封面、说明文件、WAV 和 APE，不设置格式白名单。
- 未完成下载或下载后处理只阻塞所属歌手重命名，不得据此整体禁用清理；活动下载目标、派生歌词、原子写入临时/备份文件、封面侧车及其待清理祖先目录单项跳过，其他 `.lrc` 等安全目标仍进入预览和二次确认。
- 清理目标被本地歌单引用时，预览和二次确认必须显示引用警告及受影响歌单数量；清理不自动移除或改写歌单条目。
- 当前正在播放的待清理文件单项跳过并记录原因，其他清理目标继续执行。
- 整理开始后不提供中途取消；清理阶段结束后继续执行重命名阶段，达到可恢复终态后只做一次不解码轻量刷新。
- 没有有效检查结果时禁用“整理”并提示先检查；没有清理目标但存在重命名步骤时仍可整理。

### FR-06 整理的重命名阶段

- 仅仍有效的深度验证快照可生成和执行整理计划；个别文件“检查失败”不阻止计划。
- 整理由单个歌手行发起，在清理阶段后整体处理其全部专辑，不提供复选框、批量操作或单独专辑选择。
- 歌手格式为 `<歌手>（N首）`；专辑格式为 `<专辑基础名> (N首)`，与 `easy-music` 一致。
- 只剥离名称末尾严格匹配的旧同类后缀；保留专辑基础名中的有效日期和其他文本。
- 空歌手保留并可重命名为 `<歌手>（0首）`。
- 真正为空的专辑目录由清理流程删除；仍含未清理文件且没有 MP3/FLAC 的专辑不重命名，并阻止所属歌手重命名。
- 表格持续展示歌手目标名称；逐专辑目标保留在整理计划中，但普通“查看详情”不再重复展示。用户确认整理清理范围后按顺序执行，快速统计和检查本身不得触发磁盘修改。
- 重命名从发起到终态必须持续展示真实阶段、已完成步骤数、总步骤数和当前相对目标；回滚使用独立阶段，不得用扫描进度或伪造百分比替代。
- 每个歌手执行前预检歌手及全部专辑目标；任一冲突会阻塞整个歌手，其他歌手行不受影响。
- 同一歌手内先重命名专辑，再重命名歌手；中途失败立即停止该歌手并尽力回滚，回滚不完整时报告最终真实路径。
- 整理开始后不提供中途取消，完成后只执行一次不调用 FFmpeg 的轻量目录刷新。
- 当前正在播放的本地歌曲位于目标歌手内时，阻止该歌手重命名，不自动停止播放。
- 没有任何清理或重命名步骤，或受下载、下载后处理、当前播放、目标冲突、目录能力等原因使两类步骤均不可执行时禁用该行“整理”，并展示原因；只有重命名受阻但仍有安全清理项时允许整理清理阶段并明确跳过重命名。

### FR-07 独立导航与平台范围

- 现有“工具”入口改名为“专辑抓取”，并使用独立页面和 route。
- 新增同级“歌曲整理”页面和 route；只在 Windows x64 显示入口。
- 旧 `/tools` 只作为兼容重定向，不继续作为用户可见名称。
- 本需求保留仓库其他平台的既有打包脚本，但不为歌曲整理提供其他平台资源或验收。

### FR-08 安全与任务生命周期

- 文件系统访问、FFmpeg、回收站和重命名全部在 Main 侧执行；Renderer 只通过类型化 IPC 操作。
- 所有实际路径必须位于选择根目录及当前操作歌手内；不得根据未校验的页面文本直接操作磁盘。
- 快速扫描、检查和整理都携带任务 ID；旧任务进度不得覆盖当前结果。
- 只有与当前快速统计快照一致且仍有效的深度验证快照允许整理；内部中止、整体失败或文件事实变化时禁用整理。
- 快速统计与深度验证快照不持久化；应用每次重启后必须重新发起后台快速统计，并通过可查询、可订阅的 Main 运行态让页面接管同一任务。
- 页面在当前应用运行期间通过路由切换保留结果和任务监听；离开页面不重启或中止任务。
- 快速扫描、检查和整理均不提供暂停或取消入口；运行期间目录切换、重新加载和其他同类任务入口禁用。Service 只为异常收敛、任务替换和自动化测试保留内部中止机制。
- 同一根目录快速扫描或检查被内部任务替换、异常收敛或失败时可保留上一份结果供查看，但禁止使用失效的深度验证快照修改磁盘；根目录变化时立即清空旧结果。
- 整理或恢复操作结束后立即在详情弹窗展示结果；终态轻量刷新不得覆盖当前弹窗内容。
- 成功、失败、跳过、阻塞和回滚统一由详情弹窗反馈；整理的清理范围预览与二次确认也在该弹窗完成。
- Main 必须按任务与歌手广播整理操作进度；Renderer 只接收当前操作事件，切换页面期间继续监听，旧任务或其他歌手事件不得覆盖当前进度。
- 应用关闭时若快速扫描、检查、整理或恢复仍在运行，必须阻止退出并提示等待，不得取消歌曲整理任务；任务正常结束或内部异常收敛后不得残留 FFmpeg 子进程。

### FR-09 下载任务与本地路径一致性

- `run`、`waiting`、`pause`、`error` 等未完成下载任务阻塞其路径所属歌手的整理重命名阶段；被引用音频不执行解码，与任务目标或派生歌词路径精确重合的清理项单项跳过，其他清理目标与其他歌手仍可操作。
- 下载完成后的标签和歌词写入属于后处理占用；目标文件真实 I/O 完成前继续阻塞所属歌手重命名，并保护音频、歌词及全部侧车路径。在线 Provider 30 秒未返回、封面请求超时或响应超过 10 MB 时安全降级且不得晚到写盘；目标文件 I/O 失败进入可恢复状态，仍保持占用直到重试成功或任务被移除。
- 已完成任务不阻塞重命名；重命名成功后精确更新受影响任务的固化 `filePath`，回滚时同步恢复。
- 对受影响的 `MusicInfoLocal`，必须同时更新由绝对路径构成的 `id`、`meta.songId`、`meta.filePath` 及相关缓存和索引。
- 所有引用更新只允许使用经过验证的旧/新目录前缀，不按歌曲名、歌手名或标签模糊匹配。

### FR-10 下载目录默认值与数量后缀复用

- 新安装用户默认使用“按歌手和专辑”下载目录模式；已有用户升级时保留原设置，已创建任务和已有文件不重算、不移动。
- 现有文件命名默认值保持不变。
- 结构化下载发现唯一一个严格匹配基名的 `歌手（N首）` 或 `专辑 (N首)` 目录时复用其真实路径。
- 没有候选时使用无后缀路径；多个候选时不猜测，使用无后缀路径并按批次汇总冲突提示。
- 数量后缀不作为真实计数依据，后续实际数量仍由歌曲整理扫描修正。

### FR-11 能力降级、扫描校验与异常恢复

- 磁盘卷根目录、UNC 共享根目录、Windows、Program Files、应用安装目录、应用数据目录及与其存在危险包含关系的路径不得作为歌曲整理根目录。
- 其他本地、移动磁盘和 UNC 音乐子目录先扫描，再分别检测稳定文件身份、回收站和重命名能力；能力不可用时只禁用对应操作。
- 启动、目录切换、重新加载和整理后轻量刷新均不调用 FFmpeg；每次用户显式“检查”重新完整解码当次 MP3/FLAC，不保留跨检查校验缓存，同一次检查内可按稳定物理文件身份去重解码。
- 检查采用固定上限为 2 的受控并发；每个唯一物理音频仍校验一次，结果排序、计数和异常归属不得依赖完成顺序。
- 整理执行期间阻止正常退出，并使用最小持久化操作日志记录清理、路径、引用变化和步骤结果；正常完成后删除日志。
- Windows 操作日志原子替换遇瞬时 `EPERM` 或 `EACCES` 时允许有限退避重试；耗尽后必须在任何磁盘修改前失败并保留原错误供核查。
- 异常中断后只展示未完成操作，不自动继续修改磁盘；重命名可由用户选择尝试回滚，清理由用户通过回收站恢复。

## 非功能需求

- 大目录扫描和解码不得阻塞 Renderer；进度事件必须节流。
- FFmpeg 随 Windows x64 安装包提供，不运行时下载，也不要求用户自行安装。
- 引入二进制前必须核对许可证、可信来源、包体积、开发/生产路径和缺失资源降级。
- Windows x64 使用 FFmpeg 官方下载页推荐来源中的固定 BtbN `lgpl` 构建，只携带 `ffmpeg.exe`；记录版本、构建提交、配置、SHA-256、许可证、对应源码和安装包增量，不使用 GPL/nonfree 或运行时下载。
- 文件系统核心逻辑通过临时目录、注入验证器和注入回收站 port 离线测试。
- 日志和界面不得上传用户文件、目录或扫描结果，也不得记录无关隐私路径。
- 199 首真实目录的显式检查应在结果不变、校验调用仍为 199 的前提下明显快于串行基线；快速统计不得启动校验，并发上限不得无限随文件数增长。

## 验收标准

- [ ] AC-01：Windows x64 显示“专辑抓取”和“歌曲整理”两个入口；其他平台/架构隐藏歌曲整理，旧 `/tools` 正确重定向。
- [ ] AC-02：默认目录跟随应用下载路径；“选择指定目录”“使用下载目录”、取消选择和持久化符合规则；启动后台快速统计不阻塞窗口，首次打开页面接管同一任务且不重复扫描，根目录变化后清空旧结果并自动快速统计。
- [ ] AC-03：根目录直属文件被完全忽略；歌手、专辑、深层目录及空歌手按确认模型识别；严格排除 `<base> MP3`、`<base> MP3（N首）`、`<base> MP3(N首)` 输出目录而不误伤普通包含 `MP3` 的歌手名。
- [ ] AC-04：有效 MP3/FLAC 完整解码通过；损坏样例与检查失败样例正确区分。
- [ ] AC-05：标题区无“扫描/打开目录”，页面无固定扫描状态和最近详情，“扫描目录”轨道、克制主题样式、五列表格和详情弹窗符合规则；歌手目录在资源管理器中按约定定位。
- [ ] AC-06：计数包含唯一物理 MP3/FLAC，检查失败和损坏音频仍计数，重复硬链接不重复计数。
- [ ] AC-07：整理的清理阶段只影响当前歌手行和已确认范围，所有目标进入回收站，回收站不可用时不永久删除。
- [ ] AC-08：重解析点不被跟随，只安全移除链接入口；跨歌手、跨专辑及歌手根目录与专辑之间的硬链接组不会被自动清理。
- [ ] AC-09：无法播放和检查失败的 MP3/FLAC 保持原位；普通内容重复文件不被自动删除。
- [ ] AC-10：空的非歌手目录可清理，歌手目录永不删除，空歌手正确命名为 `（0首）`。
- [ ] AC-11：行级整理目标、冲突禁用、清理后计数、重命名顺序、失败回滚和 Easy Music 后缀格式符合规则；普通详情只显示异常与阻塞，无异常时只显示一句简洁提示。
- [ ] AC-12：快速扫描、检查和整理不暴露暂停或取消入口；失败的快速扫描/检查禁止修改磁盘，完整检查中的单文件检查失败不阻止整理。
- [x] AC-13：整理终态只执行一次不调用 FFmpeg 的轻量刷新，更新真实路径与数量；操作结果使用详情弹窗展示且不会被轻量刷新覆盖。
- [ ] AC-14：专题测试、IPC/任务测试、Renderer TypeScript、lint、构建、Windows x64 安装包和人工验收通过。
- [ ] AC-15：未完成任务和下载后处理阻塞所属歌手重命名，但不误禁用其他安全清理项；活动目标及派生歌词、当前播放文件按单项规则保护，其他歌手不受影响。
- [ ] AC-16：重命名后已完成下载任务与本地歌曲的全部路径身份字段同步更新，失败回滚时一致恢复。
- [ ] AC-17：后续下载复用唯一数量后缀目录，多候选不猜测；新安装和已有用户的默认值/迁移行为符合规则。
- [x] AC-18：启动、目录切换、重新加载和整理后刷新均不调用 validator；每次显式检查重新验证当前文件，同一检查内相同物理文件只解码一次，文件身份、大小或修改时间变化会使旧快照失效。
- [ ] AC-19：危险根目录被拒绝，不同文件系统按能力逐项降级，异常中断日志可支持人工检查与回滚。
- [ ] AC-20：切换页面期间任务继续且结果保留；同目录快速扫描或检查失败可保留旧结果但禁用失效快照的磁盘操作，根目录变化清空旧结果；歌曲整理任一任务运行时关闭应用只提示等待且不触发取消。
- [x] AC-21：精确 64 位文件身份不同但转换为 JavaScript `number` 后相等的两个普通音频分别计数且不产生硬链接异常；真实硬链接仍只计一次并提供可定位核查信息。
- [ ] AC-22：操作日志瞬时 `EPERM/EACCES` 经有限重试成功，持续失败在磁盘修改前终止并可在详情中核查。
- [x] AC-23：显式检查对 199 首全部完整解码且校验调用数不变，固定并发 2 的耗时明显低于串行基线，内部异常收敛和稳定结果顺序不回归。
- [ ] AC-24：整理显示清理、重命名和引用同步阶段、真实 `已完成/总步骤` 及当前相对目标；回滚阶段单独显示，旧任务进度不污染当前操作。
- [ ] AC-25：整理失败经轻量刷新后仍能从同一歌手详情核查；下一次同歌手操作、根目录变化和应用重启按规则清理旧记录。
